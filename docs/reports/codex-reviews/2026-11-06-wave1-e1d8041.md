Reviewed `e1d8041^1..e1d8041`. This is Sieve CA code, not Babylon.js code. The commit adds no `docs/reports/` file; I reviewed its added task document and live-check runbook.

1. **P1 - CA journal is not durable before trust changes.** `engine/crates/sieve-engine/src/ca/state.rs:65–66` delegates to `write_atomic`, which writes and renames without flushing. Unlike the route journal, it never calls `sync_all`. **Scenario:** installation persists a Windows root, then power fails before its journal update reaches disk → restart loads an older or missing record, and uninstall cannot identify that trusted root. The claimed crash test does not establish this guarantee: its “crash” returns an error and allows subsequent reconciliation and saves.

2. **P2 - The live CA script silently disables existing filtering.** `scripts/live/engine-ca.ps1:92–94` replaces the entire policy with only `revision`, `engine`, and `https`. **Scenario:** run `-Step on` with `sieving:true`, custom lists, and app exemptions → those fields disappear; deserialization defaults `sieving` to false, so existing filtering stops. A read-only reproduction confirmed the dropped fields. Preserve the existing policy when changing HTTPS.

3. **P2 - Key-security evidence reports PASS without observing security properties.** `scripts/live/engine-ca.ps1:134–138` checks only that three strings are absent, ignoring the command’s exit status and requiring no actual export-policy or DACL result. **Scenario:** `certutil` returns only `NTE_BAD_KEYSET` → this check reports “not exportable” and “SYSTEM only.” Evaluating the predicate reproduced `True`. This is **reported, not observed** under standard 6.

4. **P2 - Failed CNG deletion leaks an open key handle.** `engine/crates/sieve-engine/src/ca/win/cng.rs:150–156` opens a handle without a guard and returns directly from `NCryptDeleteKey`. **Scenario:** opening succeeds but deletion fails → the handle remains allocated; every reconciliation retry leaks another. Microsoft explicitly requires freeing the still-owned handle on failure. [NCryptDeleteKey documentation](https://learn.microsoft.com/en-us/windows/win32/api/ncrypt/nf-ncrypt-ncryptdeletekey)

5. **P2 - Failed removal is displayed as “Not installed.”** `engine/crates/sieve-engine/src/ca/mod.rs:195–196` clears the displayed root before attempting removal. **Scenario:** turn HTTPS off while the store rejects deletion → the certificate remains trusted, but `status()` returns `NotInstalled` and the UI hides its thumbprint and Remove action. Keep removal-pending trust visible until deletion succeeds.

6. **P2 - The hourly threshold has no derivation.** `engine/crates/sieve-engine/src/control/certs.rs:19` introduces `TICK = 3_600` seconds without deriving it from a deadline or retry requirement; the task document merely repeats “hourly.” **Scenario:** an off-path removal fails transiently, then the store becomes writable immediately → the root remains trusted for another hour despite HTTPS being off. Under standard 1, derive scheduling from the pending operation’s deadline and an explicit retry requirement.

7. **P2 - Flags-off rendering changes unconditionally.** `src/components/sieve/settings/settings-screen.tsx:100–102` always inserts `CertificateGroup`. **Scenario:** open Settings with all switches off and no query flags → a new Certificate block and additional vertical space appear. No added report declares the permitted default-visible exception or supplies its spatial diff and re-minted baseline.

VERDICT: FIX-BEFORE-SHIP - the unflushed CA journal can leave a trusted root unrecorded after power loss.
