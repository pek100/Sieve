1. **P1 - An Off app can still be blocked.** `engine/crates/sieve-engine/src/flow/flows.rs:320`  
   The engine derives identity from its readable executable; the unprivileged UI can derive identity from a service label instead. Turn such a service’s row Off, then connect to a blocked host: the transmitted exemption key does not match the engine’s key, and the connection is dropped despite “its traffic is left alone.” The write-up acknowledges this mismatch but does not fix it.

2. **P1 - Disabling lists during startup can leave them enforced indefinitely.** `engine/crates/sieve-engine/src/lists/mod.rs:229`  
   Initial compilation captures one selection, but `compiled_for` reads the selection **after** compilation. Start compiling cached list A, then send `lists: []` during the await: A is installed, while `compiled_for` becomes empty. Subsequent iterations fetch nothing and detect no selection change. A’s domains remain blocked although every list is disabled.

3. **P2 - The list-report size bound does not hold.** `engine/crates/sieve-ipc/src/lib.rs:48`  
   `MAX_LISTED_LINE_BYTES` assumes JSON expands text at most twofold; control characters expand sixfold. Six selected lists containing 200 capped exception lines each can exceed `MAX_FRAME`. An in-memory serialization probe produced **1,163,141 bytes**, versus **1,048,576** allowed. Requesting that report fails instead of returning the skipped exceptions.

4. **P2 - The new domain settings have no editing interface.** `src/core/settings/registry.ts:212`  
   Both settings use `kind: "list"`, whose existing renderer provides only a summary, reset, and optional link. There is no `/filtering` route or domain editor. With empty defaults, opening Settings offers no way to add a blocked or allowed domain; the policy stays empty unless users edit/import settings externally.
