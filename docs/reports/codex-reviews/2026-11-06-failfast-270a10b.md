1. **P2 - Reset can leave a blocked connection waiting.** [tcp.rs:292](F:/Projects/Code/Sieve/engine/vendor/ipstack/src/stream/tcp.rs:292) sends RST using `tcb.get_seq()` and immediately closes the connection. Scenario: a forwarded client expects sequence S; the relay sends an N-byte server banner that is lost, then receives a blocked request. The reset carries S+N. An RFC 5961 client challenges that reset instead of accepting it. The closed session ignores the challenge; after removal, the non-SYN handler generates a fresh sequence number rather than using the challenge’s ACK. The client therefore remains connected until timeout. The added banner test acknowledges all server bytes, missing this case. [RFC 5961 §3.2](https://www.rfc-editor.org/rfc/rfc5961.html#section-3.2)
