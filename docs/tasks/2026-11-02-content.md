# Task: slice 9 content injection engine (stream "content")

Spec: `docs/plans/2026-10-17-https-filtering.md` 5.2, 5.5, 5.6, 7.1, 7.3 and slice 9. Branch `wf-content`.

## Goal

A pure, tested library: given a rule snapshot, a page URL and a response (status, headers, body chunks), produce the rewritten response with cosmetic CSS, scriptlets and the procedural applier injected at the start of the document, under caps, with CSP adjusted. Slice 6's HTTP path calls it later. Nothing in this stream carries traffic, reads the network outside loopback tests, or touches the system.

Out of scope, on purpose:
- wiring into a proxy path (slice 6 does not exist on main yet);
- the `filtering.content` data switch and `live_content_injects_into_test_page`: they land when slice 6 wires this in, because a switch without a traffic path would claim something false. `registry.ts`, `migrate.ts`, `sieve-ipc`, the fixture and the UI are not touched;
- downloading or caching the bundle on disk (the engine's job, slice 6 or 13);
- `$redirect` and `$removeparam` responses (slice 6), `$genericblock`, the filtering log rows (slice 12), and the "only selectors whose tokens appear" optimisation in 5.6 (next step only if the live budget fails).

## Design decisions

**D1. The pinned artefact is a JSON bundle of adblock-rust `Resource` values, not the raw uBO archive through the Rust assembler (deviates from 5.5, see Q1).**
- Alternatives: (a) pin a uBO tag older than 18a84d2 and use the deprecated assembler: a library frozen years back, so R3 becomes certain and slice 10's YouTube scriptlets are missing; (b) parse ES modules in Rust: the fragility adblock-rust's own doc warns about; (c) a JS engine in a SYSTEM service: no.
- Chosen: a dev-time script `scripts/resources/assemble-ubo.mjs <ubo-checkout> <out.json>` imports uBO's own modules under node (real `Map` and function objects, no regex parsing) and writes a sorted, deterministic JSON array: `fn.toString()` base64 encoded; `.fn` names as `fn/javascript`, others `application/javascript`; `requiresTrust` to `permission: 1`; redirect resources from `src/js/redirect-resources.js`, skipping `params` entries as adblock-rust does. It asserts every scriptlet source starts with `function ` (what `extract_function_name` needs).
- The engine only deserializes data, keeping the threat model: the hash is checked first, nothing in the bundle executes in the service, and the `resource-assembler` feature stays off. It also fits the slice 13 signed bundle, which republishes one file.

**D2. Page-level exceptions: reuse adblock-rust's matcher on derived rule text.** At compile, each `@@...$opts` line naming `elemhide`, `ehide`, `specifichide`, `shide`, `document` or `doc` is rewritten to `@@...$generichide` plus its other options and added to small private engines; asking `url_cosmetic_resources(url).generichide` on one answers "does this exception apply". That needs no second pattern matcher (S33, S14).

| Exception on the URL | specific CSS | generic CSS | procedural | scriptlets |
|---|---|---|---|---|
| none | yes | yes | yes | yes |
| `$generichide` (native) | yes | no | yes | yes |
| `$specifichide` | no | yes | no (always host-bound) | yes |
| `$elemhide` | no | no | no | yes |
| `$document` | no | no | no | no (and no rewrite at all) |

These lines count as applied in `ListReport` (5.2: a skipped exception is a defect). Limit recorded in code: a proxy has no frame tree, so `$document` on a subdocument is judged on that frame's own URL. Check the table against uBO's static filter syntax wiki while implementing; a difference is a finding, not a silent choice.

**D3. Sieve enumerates the generic selectors itself.** `report()` already parses every line with `parse_filter`. Plain-selector cosmetic rules with no hostname constraint, or whose `hidden_generic_rule()` is `Some`, and without `UNHIDE`, go into the snapshot's generic set, with one rendered `Arc<str>` stylesheet per snapshot. Page CSS is that stylesheet when `exceptions` is empty, and a re-render minus `exceptions` otherwise. Each selector is its own rule (`sel{display:none!important}`), because one bad selector in a group kills the group. Size and cost are measured (acceptance A9), as the plan expects.

**D4. Turn on adblock-rust's `css-validation`.** Required for procedural rules at all (F7) and part of the injection defence. It adds `cssparser 0.35` and `selectors 0.32` (MPL-2.0) to `sieve-filter`. Side effect: rules with invalid selectors now move from applied to skipped, which is the honest count.

**D5. Structural escaping at the emitter, not trust in the parser (S30).** One function each:
- `css_text`: `<` becomes `\3c `, non-ASCII becomes `\HEX `, control characters and any selector or `:style` value that leaves a string, comment, bracket or escape open (or has a stray closer) are dropped and counted, because rules are concatenated and one open token would swallow the rules after it.
- `js_text`: `</script` and `<!--` (any case) get `<` as `\x3c`; non-ASCII becomes `\uXXXX`.
- The payload is therefore pure ASCII, so it is valid in every ASCII-compatible page encoding and lol_html never has to transcode it. `<script` alone is not escaped: without `<!--` the double-escape state cannot start, and code like `i<script.length` must stay valid.
- The whole script is wrapped in one IIFE so scriptlet helper functions do not leak into the page's globals.

**D6. Applier: vendor the one file, transpile once, check in the output.**
- `engine/injected/procedural_filters.ts` is the pinned file, byte-identical (sha256 above, MPL header kept).
- `scripts/injected-build.mjs` (`pnpm injected:build`) runs `ts.transpileModule` as CommonJS and writes `engine/injected/procedural-applier.js`, also keeping the header.
- `engine/injected/bootstrap.js` is Sieve's own: it holds the action code (hide via `style.setProperty(..., 'important')`, remove, style, remove-attr, remove-class), first run at DOMContentLoaded, then a throttled MutationObserver.
- `include_str!` both. No `build.rs` (the workspace has none, and cargo builds must not need node). The applier and bootstrap are included only when the page has procedural filters.
- If the pinned file cannot be fetched at implementation time, stop and report; do not stub silently. The stub route is: keep the boundary, emit no procedural script, count those filters, and list it under UNVERIFIED.

**D7. Rewrite stops once injection is done.** The spec injects only at the start, so after the chunk that carried the injection the rewriter is ended and all later bytes pass through untouched. This gives the 100 MB/s budget and bounded memory for the rest of the document, and no rewriter bug can touch the body. Position rule, on the first element in parser order:
- `head`: prepend inside it;
- `html`: wait for the next element;
- anything else: insert before it.

A document with no element gets nothing. Comments, doctype and script text are handled by lol_html's tokenizer, not by searching bytes.

**D8. What is rewritten.** Only a document request (a `bool` from the caller; slice 6 owns classification, 5.2) with method not HEAD, `Content-Type: text/html`, an ASCII-compatible charset (`encoding_rs` label plus `lol_html::AsciiCompatibleEncoding`, derived rather than listed; no UTF-16 BOM), and a `Content-Encoding` of nothing or exactly one of gzip, x-gzip, deflate, br, zstd.
- Status: 200 to 299 except 204, 205 and 206. The plan says "200 to 299 and a body"; a 206 has a body but is a fragment, so injecting would corrupt it.
- `Content-Disposition`: absent, or exactly one value of type `inline` (case-insensitive, parameters ignored). An `attachment` is a download whose saved bytes and hash must match Sieve off, and the injected script would run if the file were opened locally. An unknown type counts as `attachment` (RFC 6266), and several values or a value that is not text are not something Sieve can be sure of, so all of these pass through.
- Anything else passes through byte for byte (fail open). So does a page with nothing to inject, without being decoded at all.
- Headers on rewrite: remove `Content-Encoding`, `Content-Length`, `Accept-Ranges`, `Content-Digest`, `Repr-Digest`; CSP per D10. Types come from the `http` crate, which slice 6 gets through hyper anyway.

**D9. Decoding is push-based and capped.** Write-side decoders (`flate2::write::GzDecoder`, one member, `ZlibDecoder` or `DeflateDecoder`, `brotli_decompressor::DecompressorWriter`, `zstd::stream::write::Decoder`, `default-features = false`, `window_log_max` set), each writing into one `CappedSink` that counts output and enforces the caps. Deflate picks zlib or raw from the first two bytes, as browsers do.
- `InjectLimits` declares every dial with a comment (S25): `max_decoded_bytes` 64 MiB (plan), `max_ratio` 256 applied only above `ratio_floor_bytes` 1 MiB so small repetitive pages are not reset, `zstd_window_log_max` 23 (8 MiB), `rewriter_max_memory_bytes` for lol_html's `MemorySettings`. The ratio numbers are this plan's choice, not measured; the value goes with a comment saying so.
- Over a cap, corrupt or truncated data, or the lol_html limit: `InjectError`, and the caller resets the connection (5.6). The identity path has no byte cap, since there is no bomb and memory is bounded by D7.
- Known residual risk, reported rather than hidden: `zstd` is a C decoder on hostile input in a SYSTEM service. `ruzstd` is pure Rust but pull-only, which does not fit a push pipeline. Plan 5.6 names `zstd`, so it stays.
- `Send`: slice 6 holds the rewriter across awaits, so use `lol_html::send` types; a compile-time law pins it.

**D10. CSP is one pure function (`csp::add_nonce(policy_value, nonce) -> String`), per policy.** Each header and each comma-separated policy inside one is enforced separately, so each is rewritten. For script (`script-src-elem`, `script-src`, `default-src`) and style (`style-src-elem`, `style-src`, `default-src`), find the first directive present:
- none present: no change;
- it has `'unsafe-inline'` and no nonce or hash: no change;
- found as a specific directive: append `'nonce-N'`;
- found only as `default-src`: leave it, and append a new `script-src` or `style-src` copied from it plus the nonce.

Nothing is removed. `-Report-Only` is never touched. A value that is not valid visible ASCII is left alone (our element is then blocked by the browser, which is harmless). Nonce: 16 bytes from the OS, base64, fresh per response.

**D11. Layering.** `sieve-filter` decides (no I/O, no HTML); `sieve-engine/src/inject` applies. `RuleEngine::compile` keeps its signature, since other streams call it. New items live in `cosmetic.rs`; `rules.rs` gets only the new fields, `pub(crate)` on `engine`, and the report hook.

## UNVERIFIED (live proofs for the user or a later slice)

- `live_content_injects_into_test_page`, the page-load budget and generic-stylesheet budget on 20 fixed sites: need slice 6 and real traffic.
- Browser truth: that browsers accept the rewritten CSP, ignore the later meta CSP for our elements, and exempt parser-inserted script from Trusted Types. Parsing proves structure only, unless the optional Chromium check runs. Which real scriptlets work on Trusted Types pages (plan 5.6 item 6).
- Browser truth for gzip tails, Firefox only. Chromium 1228 on loopback settled it for Chromium (headless, validator run): bytes after a member are ignored, and a later member, whole, cut or broken, is not shown. `decode.rs` now ends the body at the first member's end. That Firefox does the same comes from memory of its source (`nsHTTPCompressConv` throws away what follows the stream), not a run. If Firefox did decode later members, a multi-member page would lose them there with Sieve on; nothing errors.
- Browser truth for `css_text`: that an open string or `(` swallows later rules follows from CSS Syntax and the emitted text, not a browser run; the refusal is proved by unit test only.
- Real uBO bundle: `assemble-ubo.mjs` is tested on a fixture tree; running it on uBO 1.75.4 (latest release on 2026-11-05) needs that checkout, may reveal browser globals at import, and no real pin exists until Q1 is answered. The `src/web_accessible_resources` path comes from memory; `src/js/resources/scriptlets.js` and `src/js/redirect-resources.js` were confirmed on master.
- uBO entries marked `world: 'ISOLATED'` (for example `trusted-replace-node-text`) run in the page's main world here, because a proxy has no isolated world. Whether each still works, and whether a page can see them, is for slice 10.
- Real-list numbers: skip counts after `css-validation`, generic stylesheet size, and exception-rule skips at the default lists.
- A 304 revalidation against a cached rewritten page: if the 304 carries a CSP header, the browser may merge it and block our elements on that load (ads visible, nothing broken). Slice 6 must decide on validators; noted here so it is not lost. (Decided 2026-11-06, `docs/tasks/2026-11-06-content-wire.md` D6: a rewrite removes `ETag` and `Last-Modified`, overriding D8's keeping them.)
- Slice 10's `engine/tests/no_site_names.rs` will need to decide about `engine/injected/` if it scans there: the vendored file's content is not ours to edit.

## Open questions for the user

**Q1. Where does the scriptlet bundle come from until slice 13?** F1 makes "the engine downloads uBO's tag archive and runs the Rust assembler" impossible for any recent uBO. The library works either way, since it takes bytes and a pin; this blocks only the real pin. Plan's reason for keeping GPL code out of the repo was "Sieve has no declared licence yet", which is now gone (GPL-3.0).
- (a) Recommended: Michael runs the script at a reviewed uBO tag and publishes the JSON as an asset on Sieve's own release, with the hash pinned in code. Same channel slice 13 signs later.
- (b) Commit the JSON and embed it: no hosting, offline from first run, but each bump needs an app release and the installer grows.
- (c) Pin an old-format uBO and keep the Rust assembler as written: not recommended, because of R3 and the F2 trust hole.

Implementation does not wait on this: all tests use the fixture bundle.
