## Goal

With `filtering.https` on, a QUIC flow that `decrypt()` would intercept over TCP is answered with an ICMP or ICMPv6 port-unreachable, so the browser falls back to TCP, where interception filters it. Every other QUIC flow is decoded and relayed exactly as today. Nothing is sent upstream for a refused flow. The fallback path (silent drop) is one declared constant away, because which arm wins is a live measurement.

Done means: the offline acceptance below passes, the UNVERIFIED list and its runbook are handed over unrun, and with the switch off `handle_udp` takes today's relay path without asking anything new. This stream does not unlock `filtering.https`.

The user's rule, which binds every decision here: QUIC is decoded and refused per flow only when it would be intercepted, never blocked wholesale. Refusal follows from the filtering decision, not from QUIC.

## Design gate (clean-architecture)

- **Which law does this instantiate?** `decrypt()` of plan 4.1. No new policy primitive: refusal is the QUIC reading of `Intercept`, and the QUIC floor (`QUIC_ALPN`, `Transport::Quic`) is already in it.
- **Derived, not enumerated:** every "relayed for" case of plan section 3 (Off, excluded, not HTTP/3, ECH, session 0, forwarded, out of scope) is a `PassReason`. This stream adds no list, no host and no case of its own.
- **New quantities and their one owner:** `REFUSAL` (`quic/mod.rs`), the quote limits (`quic/icmp.rs`, from the RFCs), `QuicMeters` (`quic/fallback.rs`), the fallback samples (same).
- **Made redundant, retired:** nothing. `drain_udp` stays for blocked flows, which reply nothing and have no switch to watch (plan section 3, item 2). Overturned the same day by live runs: blocked flows now go through `quic::answer_blocked` (Version Negotiation for a client Initial, silence otherwise) and `drain_udp` is gone.
- **Thresholds:** `FALLBACK_WINDOW` bounds a measurement only and reaches no decision.

## Design decisions

**D1. One gate, after the host-level decision.** Order in `handle_udp`: decode, attribute, admit, `ctx.decide`. `Action::Drop` stays a drop: a blocked name gets no ICMP, as a blocked TLS hello gets nothing (plan section 3, item 2). Then `quic::path` answers:

```rust
pub enum UdpPath { Drop, Refuse(Refusal), Relay }
pub fn path<C: Dial>(action: Action, slot: &HttpsSlot<C>, decoded: &Decoded, who: &Who<'_>, id: u64) -> UdpPath;
```
No slot means `Relay` with nothing asked, so off is provably today's path (slice 6, D1). `relay.rs` gets a `match` of a few lines; the logic is here, where it can be tested without a `Relay`, which needs real IP Helper and egress.

**D2. The same question TCP asks.** Split out of `drive`, behaviour unchanged:
```rust
pub struct Who<'a> { remote: SocketAddr, exe: Option<&'a str>, session: Option<u32>, may_decrypt: bool, app_off: bool, names_now_ms: u64 } // Copy
impl FlowMeta<'_> { pub fn who(&self) -> Who<'_> }
impl<C: Dial> Interception<C> {
    pub(crate) fn facts_for<'a>(&self, transport: Transport, decoded: &'a Decoded, who: &Who<'a>) -> FlowFacts<'a>; // GREASE rule, speaks_to, in_scope
    pub(crate) fn before_upstream(&self, facts: FlowFacts<'_>) -> Decrypt; // reads the cached rejection, then says()
}
```
`FlowMeta` keeps its fields, so slice 6's tests and any stream building one are not touched. TCP keeps its own `active.register` before its cache read (`drive` needs the cached `Eligible` too), so `before_upstream` is what QUIC calls and TCP's two lines are reduced to the same `rejection` helper. QUIC does not register in `Active`: nothing is decrypted, so nothing has to be closed on revocation. `kind != Some(Quic)` relays without asking (F6), as TCP does for `kind != Tls`. A pass-through goes through `not_decrypted` (now `pub(crate)`), so the row and `https.passed` have one owner. **Refused exactly when `before_upstream` says `Intercept`.** There is no second condition, and a law says so.

Consequences, stated and not worked around: under browsers first a non-browser's QUIC is relayed (`floor:app-scope`), and a browser on its own DoH whose name the engine did not resolve keeps QUIC (`floor:ech`, Q2 of the slice 6 task). A first visit to a host whose verdict is not known yet is refused, and TCP then learns the verdict; a later rejection means QUIC is relayed from then on (F4). QUIC on a port other than 443 is judged like TCP on that port: ALPN decides, not a port list.

**D3. The packet, `quic/icmp.rs`, pure.**
```rust
pub fn port_unreachable(local: SocketAddr, remote: SocketAddr, datagram: &[u8]) -> Option<Vec<u8>>;
```
The quote is the app's datagram rebuilt with `PacketBuilder` (`local` to `remote`, UDP), so its IP and UDP checksums and lengths are right, cut to fit the limit. Outer source `remote`, destination `local`: the destination itself says the port is closed. Type 3 code 3 on v4, type 1 code 4 on v6. Limits are the RFCs': `ICMP4_MAX = 576` total (RFC 1812 4.3.2.3), `ICMP6_MAX = 1280` total (RFC 4443 2.4). Quoting what a real host would quote leaves nothing of ours to tune; RFC 792's 28 bytes is the floor, and a limit that cuts mid-payload is allowed by both. `None` for mixed families or a datagram too large to build, and the flow then behaves as a silent drop: the browser's own timer takes it to TCP, which is the fail-open direction. Reason for `etherparse`: F7. It moves from dev-dependency to dependency, `default-features = false, features = ["std"]` as ipstack has it, and `Cargo.lock` gains no package.

**D4. The sink.** `quic/mod.rs` declares
```rust
pub trait PacketSink: Send + Sync { fn send(&self, ip_packet: &[u8]) -> std::io::Result<()>; }
```
`tun/device.rs` gets `fn write_packet(session, meters, bytes)`, used by `TunDevice::poll_write` and by `TunSink { session, meters }`. `RelayParts` gains a required `sink: Arc<dyn PacketSink>` (S47: not optional), built in `control/routing.rs` from `tun.session`. A failed send (ring full, session closing) is counted and the flow goes on; see D3's fail-open. It lives and dies with the session, so a kill removes it with the adapter, and nothing is persisted.

**D5. The refused flow.** The fallback is a declared constant, in the shape of `exclusions::SKIP_EV`:
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Refusal { PortUnreachable, SilentDrop }
/// Plan section 3: which arm stands is decided by the live numbers, docs/live/engine-slice-8.md.
pub const REFUSAL: Refusal = Refusal::PortUnreachable;

pub async fn refuse<A: AsyncRead + Unpin>(app: &mut A, ends: (SocketAddr, SocketAddr), held: &[Vec<u8>], refusal: Refusal, sink: &dyn PacketSink, meters: &QuicMeters, idle: Duration, still_on: impl Fn() -> bool);
```
`refusal` is a parameter so both arms are tested; only `relay.rs` reads the constant. Each held datagram and each later one gets one reply, as a closed port does: at most one small packet per datagram the local app itself sent, so there is no amplification and no rate limit to invent. The flow is remembered until `UDP_IDLE` (plan section 3), so a retransmit is answered with no new attribution. The book entry closes at once, as a blocked flow's does.

`still_on` is checked per datagram: when the slot is gone (F9) the task ends, and the next datagram is a new flow on today's path. Turning the switch off must not leave a flow refused. An idle flow costs nothing and needs no wake. Flows relayed before the switch went on stay relayed, as on TCP.

**D6. What the app sees.** A log row `NotDecrypted { reason: "quic_refused" }`, shown as "Not decrypted (quic refused)" by the existing fallback, plus the host-level row `ctx.decide` already wrote. No `Blocked` and no `blocked` count: this is not a block, and the user's rule says so. The flow event closes `Relayed` with 0 bytes, with a comment saying why. See Q2. No protocol bump, no fixture change, no UI change, so no browser e2e.

**D7. The fallback measurement, `quic/fallback.rs`.** Plan slice 8 asks for it, and without it the live check would rest on reading netlogs per browser. Evidence as slice 6's D18: counts in `status.json`, no host on disk, nothing on the pipe.
```rust
#[derive(Default)] pub struct QuicMeters { refused, replies, send_failed, raced: AtomicU64, fallback: Mutex<Fallback> }
impl QuicMeters { pub fn report(&self, refusal: Refusal) -> serde_json::Value; }
```
- `refused(pid, host, first_datagram_ms)` remembers the pair in an in-memory `crate::lru::Lru` (`TRACKED = 256`). The clock starts at the first datagram read, so attribution lag is in the number (U7).
- `tcp_seen(pid, host, accepted_ms)` runs inside the slot branch of `handle_tcp` only, wrapping `decide`, so the `relay_tcp` path is not touched. The first TCP flow of that pair takes the entry and pushes `accepted - first_datagram` into a ring of raw values (`SAMPLES = 256`, S4: no buckets, the runbook takes percentiles). `accepted_ms` is read on entry to `handle_tcp`, which is the SYN.
- A TCP flow accepted before the Initial is a race, counted in `raced`, not a sample of 0 (S17). An entry older than `FALLBACK_WINDOW = 10 s` is dropped uncounted, so a later visit is not a sample.
- `status.json.quic` holds `refusal` (which arm this build is), the counts and `fallback_ms`, so the evidence labels itself.

**D8. Not built.** No QUIC termination (plan section 3). No `Alt-Svc` or HTTPS record rewriting (Q1). No Retry, no version negotiation, no connection close: an unauthenticated stateless answer would still need the Initial's keys and gains nothing over ICMP.

## Open questions for the user

**Q1. `Alt-Svc` on intercepted responses.** The TCP response Sieve relays still advertises `h3`, so a browser keeps trying QUIC and being refused until it marks the alternative broken. Removing the header in `http/` would stop most attempts at the source, but it edits every intercepted response beyond what filtering needs, and it belongs to the HTTP path, not this slice. Default: leave responses alone, and let U9 measure the cost. Changing it later is one line in `http/` with its own test.

**Q2. How a refused flow reads on the pipe.** `FlowAction` has `Relayed`, `Failed`, `Blocked`; none is true of a refused flow. Default: close it `Relayed` with 0 bytes plus the `quic_refused` log row, because the app does not read the action today (F8), `Blocked` would contradict your rule and count against the block figures, and a new variant means protocol 4 and a renamed fixture while other streams change the same file. Cost of the default: a false word on the wire, recorded in a comment. If the app ever shows the action, add `Refused` then, with the bump.

**Q3. If ICMP harms a shared socket (U5).** Default: the drop arm stands even if ICMP is faster, since a slower first fallback is better than breaking a connection the user did not ask to touch. It costs the browser's race timer on each refused first visit. Your call if the numbers are close.
