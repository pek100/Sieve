# Stream app-log: slice 4 app side and slice 12 log UI

Spec: `docs/plans/2026-10-17-https-filtering.md` slice 4 (app-side bullets), slice 12, sections 1.3, 8.3, 8.4. Worktree `F:\Projects\Code\Sieve\.claude\worktrees\wf-app-log`, branch `wf-app-log`.

## 1. Goal

1. Retire the app-hosted DNS proxy: Rust `src-tauri/src/dns/**`, its TS seams, the card, the store slice. Keep the read-only safety net and its Home banner.
2. Settings schema 5: `filtering.dns` and `filtering.perApp` gone, a stored upstream list migrated into the new encrypted `filtering.upstreams` or dropped. Law 11's key list is empty.
3. The Engine tile and block say what the engine filters, from facts only.
4. A new route `/log/`, fed through `EngineSource` with a mock, with host-level rows (slice 4), row details and row actions (slice 12).
5. The Report a broken site dialog: assembled locally, nothing sent.

Out of scope: emitting log rows and filter facts in the engine (see contract C1), `SetPolicy` carrying user rules or off apps (C2), the Home "Blocked requests" tile and the copy-law change (plan 8.5, not in this stream's spec), an upstream editor (C3), the engine's DNS Settings block.

## 2. Design decisions

D1. **`Log` is its own IPC message, not a view of `Flows`.** Design gate (S48, S52): host-level rows could be read from `FlowEvent`, but plan 8.3 rows carry path, type, rule and "Hidden N elements", which are per request and cannot be expressed per flow. Two feeds to one screen would break S14, so v1 uses the final shape from the start and host-level rows leave `url` and `request_type` null. Row shape in section 3.

D2. **`PROTOCOL` goes to 3, the fixture keeps its path `src/data/fixtures/engine-ipc-v2.json`.** A new engine message is a shape change (conventions, Engine IPC row). Renaming the fixture would turn every sibling stream's append into a rename conflict; the law compares `fixture.protocol` with the crate, not the file name. The task text's `engine-ipc-v1.json` is stale: the file on main is v2.

D3. **The window polls a tail held in Rust; it does not receive pushed events.** `subscribe_once` already owns the one subscription, so it also feeds a memory ring `EngineLog` (`ENGINE_LOG_CAP` 2000), and `engine_log_tail(since)` answers `{v, next, dropped, rows: [{seq, row}]}`. `seq` is assigned on receipt, so an engine restart (row ids restart) cannot strand the window's cursor. It matches every other seam (invoke, parse, mock) and needs no Tauri event permission. Session-only and in memory on both sides, as the plan says.

D4. **`createLogController` is a separate owner, not part of the engine controller.** One writer per store part: it alone writes `log` through `setLog` and alone calls `logTail`. It polls every `LOG_POLL_MS` (1000) only while `engineRoutes(engine)` and not paused, and emits only when rows arrived, so an idle or absent engine costs no IPC and no rerender. It reads the engine slice and writes nothing to it. The conventions line "only caller of the engine source" becomes "only caller of `probe`, `setPolicy` and the AdGuard actions". Also keeps this stream out of `engine-controller.ts`, which `wf-domain-policy` will edit.

D5. **The app ring is `LOG_RING` 2000, the view shows the newest `LOG_SHOWN` 200 that match**, with "N more not shown" (the pattern in `app-detail.tsx`). No virtualisation dependency: 200 rows at 44 px is bounded.

D6. **Normalise per row.** `parseLogTail` throws `ProtocolError` only for a wrong version or a non-array (the controller records it, the ring stays and the screen says so). A row missing `seq`, `t`, `host` or a readable outcome is skipped and counted; optional fields default to null. A bad row never empties a batch or crashes the screen (frontend-resilience). An unknown outcome kind is skipped, an unknown reason slug shows with its underscores as spaces (later slices add reasons without a protocol bump).

D7. **Facts the report needs arrive on `EngineStatus.filter`, one optional additive field**: `{lists: [{id, title, homepage, version, applied, skipped}], resource_pin}`. `#[serde(default, skip_serializing_if = "Option::is_none")]`, so the existing examples of `engine-probe-v2.json` stay byte-stable and the app parses older statuses as null. The app must not link `sieve-filter`, and a TS copy of the catalogue would be a second owner (S29), so the catalogue stays in Rust and only its facts cross the pipe.

D8. **`homepage` is a new field on `catalogue::List`** (plan 8.4 assumes it; it does not exist). Set in the `adguard!` and `uassets!` macros plus the one literal list. The issue page is derived, never listed: `issuePage(homepage)` is `${homepage}/issues` for an `https:` homepage, null otherwise. Which list: the first list among the rules applied to the page, else the first list in the facts; the dialog names it in words and offers a select to change it. No facts: the button is disabled with its reason.

D9. **The Engine says what it filters through a new phase.** `enginePhase` returns `filtering` when `status.filtering` and the lists' `applied` sum above 0, else `routing` as today. `ENGINE_STATE_TEXT.filtering` is "Filtering hosts"; the detail names the list and rule counts, says host names only unless `status.decrypting`, and says off apps pass through. `engineRoutes` and the controller's passed check cover both phases. Home shows only the state text, so the Home copy law (no "blocked") still holds. `EngineCard` lists each list's applied and skipped counts (slice 4 acceptance: "the per-list applied and skipped report is shown in Settings").

D10. **Registry help makes no claim about what is blocked.** The static help on `filtering.engine` and `sampling.enabled` cannot know the build's facts, so "Nothing is blocked yet" goes, and it points to the Engine block, which derives. `APP_OFF_MEANS` becomes "Off: Sieve passes this app's traffic through untouched and stops charting it." (plan 8.2 wording), which depends on C2 landing in the same release.

D11. **The safety net keeps its behaviour and loses the controller.** `src/data/safety-net.ts`: `WindowsDnsSource {windowsDns()}`, `createTauriWindowsDns`, `createMockWindowsDns({pointed})`, `createSafetyNet({source, settings, notices, clock}).bind()`. The newest reading stays inside the closure: nothing renders it any more, so it needs no store part. `strandedAdapters(windows)` loses `status`, because no Sieve listener can exist on port 53 now. `STRANDED_DNS_TEXT` is unchanged word for word. `src/core/dns.ts` stays at its path, cut to the safety net (the plan's wording), with `LOOPBACK_DNS` a set.

D12. **`adguard_running` and `adguard_in` go too.** Only the DNS slice read them; the engine probe reads AdGuard's service. S52: name what became redundant and retire it. `hickory-proto`, `reqwest` and the `Win32_System_Diagnostics_ToolHelp` feature go with them if `cargo` confirms no other user; `tokio` stays for the pipe.

D13. **Migration 4 to 5 (`retireDnsProxy`).** Deletes `filtering.dns` and `filtering.perApp`. Of a stored `filtering.upstreams` it keeps the elements that parse as DoH, DoT or DoQ, as the first entries followed by the defaults not already present; none parses (every list an old build could store: bare addresses): the key is deleted, so the defaults apply. Never carries a plain address forward, because the engine sends no plain DNS. Parser: new `src/core/upstream.ts` (`parseUpstream` returns `{kind: "doh"|"dot"|"doq", ...}` or null; `https://host[:port]/path`, `tls://host[:port]`, `quic://host[:port]`), element spec `upstream` in the registry now calls it. New default: the two templates of plan 1.4. `unavailableUntil` comes off because the key is kept and shown; `setting-row.tsx` already renders a list as a summary with Reset.

D14. **`unavailableUntil` stays as a mechanism, law 11 changes form.** The plan empties the key list and does not remove the attribute. With an empty list every per-key loop would pass vacuously (S26: a law that cannot fail is not a law), so `tests/laws/unavailable.test.ts` keeps the real registry for "the list is exactly empty, the retired keys are not in `REGISTRY`, schema 5 drops them from every older schema", and the behaviour moves to `src/core/settings/unavailable.test.ts`, which mocks `isAvailable` false for one real key and runs read, write, search, export, import and reset. Step 3 (`offUnavailableSwitches`) stays: old decoders are load-bearing (S39).

D15. **Row actions write settings through pure reducers.** `src/core/log-actions.ts`: `rowActions(row)` says which apply (Unblock only on Blocked with a rule; Block only on Passed through with reason `no_rule`, since on `exception` and `app_off` the rule it adds would change nothing; Do not decrypt except on Not decrypted; Copy URL only when `rowUrl(row)` is not null; Report always), `unblockRule(host)` is `@@||host^`, `blockRule(host)` is `||host^`, `addLine(list, line)` dedupes. An IPv6 host goes in a rule in brackets (`||[2001:db8::1]^`), the only form adblock-rust matches (`an_ipv6_rule_matches_only_in_its_bracketed_form` in `sieve-filter`), and bare in the exclusions, the only form that parser reads. Unblock and Block open one preview dialog that shows the exact rule before anything is written, then a toast with Undo; confirming also closes the details sheet, because a modal left open makes the toast unclickable. When the line is already there nothing is written: the toast says so and offers no Undo, because an Undo would remove a line this action did not add. New keys, appended: `filtering.userRules`, `filtering.exclusions` (`list` of strings, default empty; E10 syntax for exclusions). The toast says the rule was added, not that it is in force, until the engine reports it (C2).

D16. **Query strings are out by default.** The URL field starts with `stripQuery(url)`. When the row had a query, one button "Add the query string back" restores it; whatever is in the field at copy time is what the report holds, so a query the user leaves or types stays. S24 and S27: never infer the permissive state for a token-bearing string. `#fragment` is stripped with it. Host-level rows have no query at all; the mock's request-level examples exercise this.

D17. **The report holds exactly the listed fields**: page URL, browser exe, lists with versions, rules applied with their lists, resource pin, Sieve version. No pid, session, IP, flow id or other rows' hosts. So a row whose URL or host is an IP address prefills no URL (`reportUrl`); an address gets in only if the user types it. "Rules applied": ring rows whose host equals the URL's host (and whose exe equals the browser, when known) and that carry a rule, each rule once. `src/core/report.ts` is pure (`buildReport(facts): string`).

D18. **Opening a page goes through one seam.** `tauri-plugin-opener` (the insufficiency: nothing installed opens the default browser, and law 8 bans `ShellExecuteEx`), capability `opener:allow-open-url` scoped to `https://github.com/AdguardTeam/*` and `https://github.com/uBlockOrigin/*`, `Desktop.openExternal(url)`; the browser mock uses `window.open(url, "_blank", "noopener")`. "Open issue page" writes the clipboard first; a refused clipboard leaves a notice and the text selectable, and the page still opens. Sieve version: `Desktop.appVersion()` (`@tauri-apps/api/app`), "browser preview" outside Tauri. No fetch, no report text in any URL.

D19. **Rows are not a table.** Each row is a `div` holding a stretched `<button>` (opens the details sheet) and a sibling `IconButton` menu, so no button nests in a button. Columns at 1280: time, icon, host (mono), path (truncated, full in `FloatingTooltip`), type, outcome in words, rule (mono) and list. At 375: time, icon, host and outcome on one 44 px line; the rest is in the sheet. Outcome is words first, with `text-blocked` only on Blocked. No chips, dividers or containers. Details and row menu render one `LogActions` component.

D20. **Nav entry appended last** (`{ href: "/log", label: "Log", icon: "list" }`), per conventions; the `list` icon already exists in `RouteDef` and `top-bar.tsx`.

  ```rust
  // sieve-ipc, append to ENGINE_TYPES: "log"
  EngineMessage::Log { rows: Vec<LogRow> }          // on the Subscribe connection, batched at FLOWS_BATCH_MS, session-scoped like flows
  pub const LOG_PER_FRAME: usize = 200;
  pub const LOG_URL_MAX: usize = 2048;              // the engine truncates to these raw bytes; they bound one row, not a frame
  pub const LOG_RULE_MAX: usize = 1024;
  pub fn log_frames(rows: &[LogRow]) -> Result<LogFrames, FrameError>;   // send these messages, never chunks by count: escaping can pass MAX_FRAME, and a refused frame ends the stream
  pub struct LogRow { id: u64, t: u64 /* ms epoch */, flow_id: u64, pid: Option<u32>, exe: Option<String>,
      session: Option<u32>, kind: FlowKind, host: String /* name, else the remote IP */, remote: String,
      url: Option<String>, request_type: Option<String>, outcome: LogOutcome,
      rule: Option<String>, list: Option<String> /* catalogue id, or "user" */ }
  #[serde(tag = "kind", rename_all = "snake_case")]
  pub enum LogOutcome { Blocked, Redirected, ParamsRemoved, Hidden { elements: u32 }, Scriptlets { count: u32 },
      Passed { reason: String }, NotDecrypted { reason: String } }
  pub struct FilterFacts { lists: Vec<ListFact>, resource_pin: Option<String> }
  pub struct ListFact { id: String, title: String, homepage: String, version: Option<String>, applied: u64, skipped: u64 }
  // EngineStatus gains: filter: Option<FilterFacts>
  ```

## 7. Open questions for the user

- Q1. **Should apps the user turned Off appear in the log?** The Off promise says Sieve "stops tracking" the app; plan 8.3 has "Passed through (reason)", which is the clearest proof an exemption works.
