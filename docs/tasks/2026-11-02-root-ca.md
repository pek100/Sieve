# Task: slice 5, root CA and certificate status

Spec: `docs/plans/2026-10-17-https-filtering.md` 2.1 to 2.5, 1.3, 1.5, 7.2, 7.3, 8.1, slice 5. Branch `wf-root-ca`, worktree `.claude/worktrees/wf-root-ca`, based on main f0fe2cb.

## Goal

The engine can own one per-install root CA: a CNG key it cannot export, a root with the 2.1 limits, trusted in `LocalMachine\Root` and by Firefox, rotated silently before expiry, and removed on every off path. It can mint leaves through an API slice 6 will call. The app shows the facts in a Certificate group in Settings > Filtering.

Nothing decrypts in this slice. `decrypting` stays false, and no agent ever runs a real key, store or registry write: those sit behind traits, tested with fakes, and their real proof is listed under UNVERIFIED.

Done means: the acceptance commands below pass offline, and the UNVERIFIED list is handed over unrun.

## What a probe already settled

Run on 2026-11-05 in a scratch crate outside the repo, in-memory key only (rcgen 0.14.10, aws-lc-rs 1.19.0, aws-lc-sys 0.47.0, x509-parser 0.18.1, rustc 1.93.1):

- The plan's `RemoteKeyPair` is gone from rcgen. The seam is now the `rcgen::PublicKeyData` and `rcgen::SigningKey` traits, implemented by a type that holds only public bytes and a sign call. A self-signed root and a signed leaf both worked through it.
- `IsCa::Ca(BasicConstraints::Constrained(0))`, `KeyCertSign` + `CrlSign` and `ServerAuth` give exactly: keyUsage (critical), EKU serverAuth, SKI, basicConstraints CA:true pathLen:0 (critical).
- A plain leaf (`IsCa::NoCa`) has **no SKI**, which 2.5 requires, and rcgen's default subject is `CN=rcgen self signed cert`. `IsCa::ExplicitNoCa` writes the SKI and CA:false. Clearing `distinguished_name` makes the SAN critical by itself. AKI needs `use_authority_key_identifier_extension = true`. With those the leaf carries what 2.5 asks for, and its signature verified against the root's public key.
- `Issuer::from_ca_cert_der(der, key)` (feature `x509-parser`) rebuilds the issuer from the root's DER, so no parameters need storing.
- `SerialNumber::from_slice` of 16 bytes with the top bit set encodes as a positive 17-byte integer, within the 20-octet limit.
- Minting with an in-memory P-256 signer: about 25 to 37 us each. This says nothing about `NCryptSignHash`.
- aws-lc-sys builds on this machine with CMake present and NASM absent, using aws-lc-rs feature `prebuilt-nasm`. This is the build note 2.7 asks for.

## Design decisions

**1. Time is a parameter.** `Ca::reconcile(wanted, now_ms)` and `Minter::leaf(req, now_ms)` take the time; only the service loop reads `policy::wall_ms`. There is no clock trait: the pure core stays deterministic (S15), and fake-clock tests just pass numbers.

**2. One reconcile function is the only path that changes trust.** It covers turn on, turn off, rotate, retire and retry, so no path can forget a step. It is sync and blocking; the service runs it in `spawn_blocking`.

| State | Action |
|---|---|
| `wanted` false | Remove every root, key and the Firefox policy. Keep a record until its removal succeeded. |
| `wanted`, no root, not withdrawn | Create and install. |
| Active root reached `not_after - ROTATE_BEFORE` | Rotate. An expired root (a machine asleep or off past both dates) rotates the same way, with the old root's removal due at once. |
| Retiring entry reached `remove_at` | Remove its root, then its key. |
| Active root missing from the store, or its key will not open | See decision 6. |

**3. Crash safety is a record first, like the route journal.** `ca.json` is written (atomically) before each external write:
1. Add `{key_name, thumbprint: null, remove_at: 0}` to `retiring`, then create the key.
2. Build the DER, record its thumbprint, add it to the store.
3. Promote it to `active`; the previous root moves to `retiring` with its `remove_at`.

A crash at any step leaves an entry whose `remove_at` has passed, so the next reconcile cleans it up. A test injects a failure at every step and asserts that a fresh `Ca` from the saved file ends clean.

**4. Facts have one owner (S51).**
- `ca.json` holds only key names, thumbprints, `remove_at`, `firefox_policy_set`, `last_rotation_ms` and `withdrawn`.
- The certificate itself is read back from the store by thumbprint (`RootStore::read`), which also answers "is it installed". `not_after` comes from that DER.
- No certificate or key bytes go in a file, so the 7.2 grep stays meaningful.
- The engine derives `state` (including Expires soon: `now >= not_after - ROTATE_BEFORE`, meaning rotation is overdue) and sends it; the app never recomputes it.

**5. `ca.json`, not `state.json` (deviates from 2.3).** `record_owner` overwrites `state.json` on every install and its struct has `deny_unknown_fields`, so an update would erase the thumbprint and strand the root. Add an as-built note to 2.3.

**6. A root that vanished is not silently replaced.** If the store no longer has the active root (a person removed it, or another tool did), or its key cannot be opened, then:
- the leftover root and key are removed where possible, and `withdrawn` is set;
- status says Not installed, with the reason in `last_error`;
- `minter()` is None, so slice 6 passes through.

Only the user's act clears `withdrawn`: Reinstall, or the switch off and on. Reason: 7.3 forbids installing a root without an explicit act, and consent to rotate does not cover undoing someone's removal.

**7. Removal is by recorded thumbprint only (1.5), never by name.** A subject-prefix sweep could delete a foreign certificate. A `ca.json` that cannot be read is an error reported in status and by the verb, never guessed around, and no new root is made while it stands.

**8. Rotation timing.** Constants in `ca/mod.rs`:

| Constant | Value | Source |
|---|---|---|
| `ROOT_LIFETIME` | 365 d | 2.1 |
| `ROTATE_BEFORE` | 30 d | 2.1 |
| `LEAF_MAX_LIFETIME` | 7 d | 2.5 |
| `CLOCK_SKEW` | 1 h | 2.5; also applied to the root's notBefore, so a leaf's backdating never predates its root |
| `LEAF_CACHE_SIZE` | 4096 | 2.5 |

The old root's `remove_at` is `rotated_at + LEAF_MAX_LIFETIME + CLOCK_SKEW`. That reconciles 2.1 ("once its last leaf has expired") with the user's table ("after the switch"), and a test asserts that no leaf outlives it. The subject's date is each root's own creation date, so a rotated root never shares a subject with its predecessor. Reinstall removes the old root immediately instead of retiring it.

**9. Keys.** `KeyStore { create, open, delete }` returns `RootKey`, which is `rcgen::SigningKey` plus `Send + Sync`. Each root gets a new random name (`Sieve root <16 hex>`), so the old key can never be reused (2.4). Tests use `MemoryKeyStore` under `#[cfg(test)]`. `CngKeyStore` is the only code that names `NCrypt*`:
- machine scope, Microsoft Software KSP, export policy 0;
- the DACL set before `NCryptFinalizeKey`, from the SDDL `D:P(A;;GA;;;SY)`.

Two pure functions in `ca/cng_blob.rs` carry the format risk and are tested without CNG:
- `NCryptSignHash` returns P1363 `r||s`, but X.509 needs DER. `p1363_to_der` is tested by signing with aws-lc-rs `ECDSA_P256_SHA256_FIXED_SIGNING` and verifying the converted result with `ECDSA_P256_SHA256_ASN1`, including values with a high bit and leading zeros.
- `ecc_public_blob_to_point` turns a `BCRYPT_ECCPUBLIC_BLOB` into `0x04||X||Y`, and refuses a wrong magic or length.

**10. Store and Firefox.**
- `RootStore { add, read, remove }`: `add` builds a context with `CertCreateCertificateContext`, sets the Server Authentication property, then `CertAddCertificateContextToStore(CERT_STORE_ADD_NEW)`, so a root is never in the store without its property. `read` is by SHA-1 hash, and `remove` of an absent root is success.
- `FirefoxPolicy { installed, read, set, delete }`: `set` happens only when Firefox is installed and the value is absent, and records `firefox_policy_set`. Removal happens only if Sieve set it, and only while the value is still 1. Empty policy keys are then removed upward.
- Thumbprint is the SHA-1 of the DER, lowercase hex, as `certutil -store Root <hash>` takes it. New dependency `sha1` 0.10 from the RustCrypto family `sha2` already comes from: the store's identity is SHA-1 and the fakes need it without Windows.
- The policy is re-applied on each hourly reconcile, so a Firefox installed later is covered.

**11. The uninstall verb runs as admin, but the key's DACL is SYSTEM only (a gap in 1.5 and 2.2).** An elevated admin cannot be assumed able to open or delete that key. So:
- Admin rights do reach the store and HKLM, so the `trust` step removes roots and the Firefox policy directly from the verb, first, as 2.4 demands.
- The `ca keys` step starts the service with the argument `purge-ca-keys` (`Service::start`). `service_main` sees it after the folder check, deletes the recorded keys as SYSTEM, updates `ca.json` and stops, without starting routing or the pipe.
- Uninstall's order becomes routes, stop, trust, ca keys, delete service, program data.
- If entries remain unremoved, `remove_program_data` keeps `engine\ca.json` and reports FAILED, so rerunning uninstall still knows the thumbprints.
- While `removal::remaining` says anything, `delete service` also keeps the service, set to start on demand, and reports FAILED: a rerun reaches the keys only through it. This is the one exception to "every step runs". The other steps still run. The NSIS hook keeps the engine's files when the verb fails, so the rerun has an exe.

`restore` and the watchdog do not touch the CA: the root is not network state and changes nothing while the engine is stopped (the rule's trust paragraph).

**12. Leaf API for slice 6 (`ca/leaf.rs`).**

```rust
impl Ca { pub fn minter(&self) -> Option<Arc<Minter>> }   // None: no installed, in-date root; pass through
pub struct LeafRequest<'a> { pub host: &'a str, pub upstream_not_after_ms: u64 }
impl Minter {
    pub fn leaf(&self, req: LeafRequest, now_ms: u64) -> Result<Arc<Leaf>, CaError>;
    pub fn root_der(&self) -> &[u8];
    pub fn leaf_key_pkcs8(&self) -> &[u8];
}
pub struct Leaf { pub der: Vec<u8>, pub not_after_ms: u64 }
```

- `rustls` stays out until slice 6; these are bytes.
- One `Minter` per root, holding the LRU, so rotation replaces the cache with no invalidation logic. The leaf key is generated once per engine run in `Ca::new`, memory only.
- A host is lowercased and must be a valid DNS name. An IP, a wildcard or an empty name is an error, which slice 6 treats as pass-through.
- `notAfter` is the earliest of upstream, now + 7 d and the root's. A result not after now is an error.
- A cached leaf is reused only when its `not_after` is after now and not later than that same computed cap, so a renewed upstream with an earlier expiry never gets an older, longer leaf.
- Subject empty with critical SAN: one rule, no 64-character CN limit to special-case for long hosts. Slice 6's live check in Edge, Chrome and Firefox covers it.
- The LRU is a `HashMap` plus a `BTreeMap` of ticks, about 30 lines. A crate is not justified for this.

**13. IPC, appended.** `ClientMessage::CertStatus`, `ClientMessage::InstallRoot`, `EngineMessage::CertStatus(CertStatus)`, `Policy.https`.

- `InstallRoot` is refused unless `policy.https` is on. No message signs, exports or mints, and the existing law keeps checking.

Bump `PROTOCOL` and `SUPPORTED` to 3 and the probe's `v` to 3 once. Fixture file names stay, to keep merges small; the `v` and `protocol` fields inside change. **Merge note:** if another stream also bumped to 3, no second bump is needed, since no v3 was ever released. **15. App.**

## Open questions for the user

The build proceeds on the stated default; each default can change without rework.

1. **May `filtering.https` be switched on before interception exists (slice 6)?** Default, from the plan's "cannot be on without slice 6": no, it stays hidden, and the live check drives it through `policy.json` with the app closed. The alternative is to show the switch now, which means installing a trusted root that does nothing yet, but lets you try off and Remove in the real window. The change is one registry attribute and law 11's list.
2. **Should turning `filtering.engine` off also remove the root?** Default, from 2.4: no, only `filtering.https` off removes it, so an engine pause does not churn roots. The alternative is `wanted = engine && https`, which leaves no root while routing is off, at the price of a new root and key per pause. The change is one line in `control/certs.rs` and its tests.
