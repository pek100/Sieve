## Goal

With `filtering.https` on, a browser's TLS flow is terminated by the engine and every request in it is filtered by full URL (block, redirect, removeparam). Every flow that must not be decrypted reaches the real server untouched, byte for byte, so the client judges the real certificate itself. Nothing in HTML changes. `filtering.https` stays unavailable to users: this stream builds behind the switch and does not unlock it.

Done means: the offline acceptance below passes, the UNVERIFIED list and its runbook are handed over unrun, and with the switch off the production TCP path is the untouched `relay_tcp`.

## Rules that bind this task

- Do not change `ENGINE_SLICE_6`, `unavailableUntil` or law 11. Do not change `flow::relay::relay_tcp` (`scripts/check-relay-experiments.mjs` audits it).

## Design decisions

**D1. One path per flow, chosen once.** `stack::relay::handle_tcp` asks `Relay.https` (an `HttpsSlot`). `None` (switch off, no minter, not sieving) means today's `relay_tcp`, unchanged, so off is provably the old path. `Some` means `tls::intercept::run`. Reason: fail-safe, and the source audit stays clean. TENSION (S14): two first-byte loops exist while the switch can be off; recorded in the module header, and both share `TcpClassifier`.

**D2. Deferred verification, off the runtime.** The upstream rustls client gets `CapturingVerifier`: it records the chain and OCSP staple and asserts, while handshake signatures are still checked by the provider. Nothing from the client is sent until `tls::upstream::verify` returns. Order:
1. `Eligibility`: rustls `WebPkiServerVerifier` over `tls::public_roots()`, inline, no OS, no network. `UnknownIssuer` gives `NonPublicRoot`, any other failure gives `Invalid`. Because Sieve's root and any other interceptor's root are not in that set, "must not anchor in Sieve's own root" needs no check of its own (S52).
2. `TrustVerifier` (trait): production is `rustls_platform_verifier::Verifier`, run on `spawn_blocking` behind a semaphore (`TRUST_CONCURRENCY`) and a timeout (`TRUST_TIMEOUT`). A timeout gives `Unavailable`, which passes through and is not cached. Tests inject a fake.

Upstream `Resumption::disabled()` (F3) and no early data. Reason: a private root never touches CryptoAPI, a slow OCSP never stalls the relay, and the order is what makes pass-through free.

**D3. No real platform call offline.** The roots of eligibility and the `TrustVerifier` are injected values, so rcgen chains need no store. A construction-only test builds the production verifier; verification by it is `live_*` only.

**D4. Flow order in `tls::intercept::run`.**
1. First bytes: select over client read (into `TcpClassifier`) and upstream read (cancel-safe, own buffer). A server that speaks first is not TLS: forward it, and the flow can only splice. This loop is `tls::first_bytes`, not a change to `relay_tcp`.
2. Host-level decision, `Relay::decide`, as today. Drop closes.
3. `decrypt` with the cached verdict. PassThrough: replay held bytes on the unused SYN-time socket (U0) and splice.
4. Upstream handshake on U0, with the client's SNI and filtered ALPN, under `UPSTREAM_HANDSHAKE_TIMEOUT`. Then `verify`.
5. `decrypt` with the verdict. PassThrough: a fresh TCP through `Connector` (the `Egress` seam), replay, splice; a failed connect closes the app side and the book says Failed.
6. Intercept: `Ca::minter()`, `Minter::leaf`; `CaError::{Host, Expired}` or no minter passes through (as the CA docs promise). `TlsAcceptor` over `Prefixed<A>`, which replays the held bytes. Then `http::serve`.

Reason: plan 2.6 as written, and no client byte is answered before step 6.

**D5. Verdict cache, `tls::verdict`.** Key (host, port), value verdict, leaf SHA-256 and expiry, the earlier of notAfter and now + 24 h. A cached rejection skips the upstream handshake. A cached `Eligible` with the same leaf hash skips only the CryptoAPI call; the handshake and eligibility always run, since each client connection has its own upstream. `Unavailable` is never cached. LRU extracted from `ca/leaf.rs` into `crate::lru` on this second use (S33). EV and client-certificate facts live in the store only (D6), so each fact has one owner (S29). A known leaf keeps its expiry: the 24 h run from the trust call really made, or a host visited daily would never reach it again (validator's bug 1).

**D6. The store is three layers behind one snapshot.** `ExclusionSlot` holds `Arc<ExclusionSet>`, swapped like `FilterSlot`:
- `user`: `Policy.exclusions` through `exclusions::parse_line`, never persisted a second time;
- `list:<id>`: replaced at each refresh;
- `auto:*`: `engine\exclusions.json`, schema `{v, entries}`, `policy::write_atomic`. `auto:ev` carries an expiry; `auto:client-cert` and (slice 7) `auto:pinning` do not. Each reason keeps its newest `MAX_PER_REASON`, so a flood of one cannot grow the file or push out another. `add_auto` only queues the file: `auto::Writer` saves on its own thread, at most once per `WRITE_SPACING`. An unreadable file means `floor:no-exclusion-list`, never an empty store (S24).

The entry reuses `Exclusion`. The set is linear over app-limited entries and indexed by host suffix for the rest, since the live list may hold thousands of lines; `decrypt` runs per flow, not per packet.

**D7. Sources are data, and the user's decision is the default.** `exclusions::lists::SOURCES` declares each source:
- `sensitive`: `crates/sieve-filter/data/sensitive.txt` (Sieve-owned, seed compiled in, outside `src`), replaced by the signed copy at `update::data_path(dir, &Kind::List("sensitive"))` when present and parseable;
- `banks, sensitive, issues, windows, firefox` of HttpsExclusions: fetched with the `lists::Fetcher` seam and `lists::cache::Cache`, 24 h, `If-None-Match`, built and tested with a fake, **`enabled: false`** until Q1 is answered.

`floor:no-exclusion-list` holds until every enabled source has loaded once. The seed covers the decided categories (banking, payments, health, password managers, OS update endpoints); government is mostly the floor's. One format, the existing parser. A tampered list can only add pass-through.

**D8. Browsers first is a floor fact.** `floor:app-scope`: until the user widens scope, only exes Windows itself declares as browsers are decrypted. `exclusions::browsers::BrowserSet` reads `Clients\StartMenuInternet\*\shell\open\command` under HKLM and each loaded `HKU\<sid>` (read only; reading is always allowed), behind a trait, compared by full exe path. Reason: derived, no list of names (S49); an Electron app is not registered, so sibling-file heuristics that would catch Discord are avoided; Tor Browser and portable builds simply stay undecrypted, the safe direction. `Switches.scope` is `Browsers` today; `All` is a one-line widening after slice 7 is proven live.

**D9. The ECH fact means "a real ECH cannot be ruled out".** `FlowFacts.ech` is `hello.ech && !names.has(remote_ip, sni)`. If the engine's own DNS answered this SNI for this address, the app resolved the SNI itself, so it is the real target and the extension is GREASE. A browser using its own DoH, or a real ECH whose outer name was not looked up, leaves the fact true and the flow passes, as plan 2.9 says. A wrong "GREASE" cannot leak: the client treats our answer as ECH rejected, authenticates the public name, and retries without ECH under a normal decision (RFC 9849, middleboxes). Plan 2.9 and 4.1 get a dated note. See Q2.

**D10. `Hello` grows `versions`, `suites`, `groups`** (additive, parsed in `sni.rs`). `tls::server::speaks_to(&hello)` is true when the client shares a version of 1.2 or later, a suite and a group with `tls::provider()`. False gives `floor:protocol` before any answer (threat model, "Downgrade").

**D11. `decrypt` is pure and lives in `sieve-filter`.** It has no I/O, clock or Windows, so property tests can hammer it and QUIC calls the same function (S14, S29). `upstream: None` means "not known yet": Intercept then means "eligible, go and ask", which is exactly what slice 8 needs. `FlowFacts.transport` makes the ALPN floor ask for `h3` on QUIC and `h2`/`http/1.1` on TCP. Order: switch, floor, store, app Off, intercept. A missing exe or session is a pass-through, never a guess (S24), which also covers `Owner::Unknown`, though `may_decrypt()` is true for it.

Declared tables, annotated in `exclusions.rs`, not code paths: `RESTRICTED_TLDS` (`gov, mil, bank, insurance`), `GOVERNMENT_LABELS` (`gov, gouv, gob, govt, go, gv`), `HTTP_ALPN`, `NO_ALPN_PORTS` (443, 8443). The suffix check uses `psl` (already in the tree through adblock, added as a direct dependency): a known public suffix of two or more labels whose label before the TLD is in the table, so `go.com` is not caught and `go.jp` is.

**D12. WebSocket: HTTP/1.1 Upgrade spliced; extended CONNECT not advertised.** Deviation from 2.8's wording. Per F7, advertising it without knowing the upstream breaks working sites, and waiting for the upstream's SETTINGS costs a round trip on every connection. Without the setting, RFC 8441 clients open an HTTP/1.1 connection for the WebSocket, whose ALPN reaches the upstream as `http/1.1`, and that is spliced. An h2-only WebSocket server then refuses the offer, which gives `floor:protocol`, a pass-through, and the behaviour the user has without Sieve. The URL rule runs before the upgrade (`websocket` type); nothing is filtered after it.

**D13. Requests.** `http::facts` is the one owner of url, type, initiator and document-ness (5.2): `Sec-Fetch-Dest`, else `Accept` and extension. `RuleSet::check_request` is new beside `check_url` and returns verdict, rule, list, redirect and rewritten URL, with the user's engine first and the lists asked on the rewritten URL. A block yields to a `$document` exception on the initiator unless `$important`, the same rule as `after_block`.
- **Block:** 403, empty, `no-store`. Nothing goes upstream.
- **Redirect:** the `data:` resource decoded into a 200 with its type, `Access-Control-Allow-Origin: *` and `Cross-Origin-Resource-Policy: cross-origin`, nothing upstream. A rule whose resource is missing (no bundle pinned today, `RESOURCE_PIN` None) stays a block.
- **Removeparam:** a GET or HEAD document gets 307 to the clean URL, so page script cannot read the parameter either; a subresource is rewritten in place. The rewritten URL has no parameter, so it cannot loop.

Every request gets a log row with url and type; bodies, cookies and auth headers are never logged (7.1).

**D14. 421.** Before rules and before the upstream: host differs from SNI (case, trailing dot normalised) or an explicit port differs from the flow's port. Both h1 (`Host`, with `Connection: close`) and h2 (`:authority`). The leaf names only the SNI, but a client may still coalesce, and the exclusion check ran only for the SNI.

**D15. hyper both ways, one upstream per client connection.** Same protocol on each side, since ALPN came from the server (2.8). `preserve_header_case` on h1. Hop-by-hop headers are dropped except on the upgrade path. Either side ending ends the other (GOAWAY or close), since there is no pool to fall back on. No ALPN: h1 only if the first decrypted bytes parse as HTTP, else plain copy between the two TLS sessions. h2 windows are declared dials, set for the throughput budget and adjusted from the offline bench.

**D16. Client-certificate and EV.** The `ResolvesClientCert` records "asked" and returns none; checked after the handshake. Asked with a chain that passes eligibility: `auto:client-cert` entry, pass through on a fresh socket. Asked with any other chain: the verdict goes in the bounded cache and nothing is written, since anyone can ask. Asked with no chain: a handshake that did not finish. A post-handshake request surfaces as a rustls error on an open connection: close, log, entry. EV: OID 2.23.140.1.1 in the leaf's certificate policies with `Switches.skip_ev` (constant true, no setting until a UI shows it, S35) adds `auto:ev` and passes through.

**D17. Revoked while connected.** `tls::active::Active` registers each flow that may decrypt by host with a `watch` close signal, before it reads the verdict cache and dropping out before any pass-through, so no close falls in the 25 s before decryption. A verdict of revoked closes that host's flows; the verdict is stored first, so a flow registering later reads it from the cache. Turning the switch off closes all of them and is latched, for a flow that took the slot just before. A close before the client has an answer becomes a pass-through; after that it ends the flow, and `ClientWatch` does not hear of it. Revocation is learned only at a handshake (2.6), since no timer polls.

**D18. Evidence of key exchange without a disk log.** Plan 7.1 keeps the log in memory only, so hosts do not go in `status.json`. `Meters` counts negotiated groups per side and `status.json.https` reports them (the local-only extension `experiments` already uses). The runbook reads the delta around one site. No IPC field. Slice 12 may show per-flow facts later.

**As built (seams that moved in the build, the names above otherwise hold):** `ResponseHook` has a first question, `fn wants(&self, req, status, &HeaderMap) -> bool`: `begin` needs the first data frame, and holding a response head for it would stall a server-sent stream that stays quiet after its headers, so a response no hook wants streams from its first byte. A rewrite removes `Content-Length` itself in `begin`, which holds the headers. `ExclusionSlot` adds `get_at(now)`, and `switches(https, root_ready)` takes the two facts it does not own. `Decrypt`'s reasons are `PassReason::{SwitchOff, Floor(Floor), Stored(Source), AppOff}`; `sieve_filter::exclusions::restricted_suffix(host)` is public for the DNS stream. `FlowMeta` also holds `id`, `remote`, `app_off`, `names_now_ms` and `decide`. The connector seam is `tls::intercept::Dial` (not `dns::Connector`, whose `tcp` returns a `TcpStream`, so the duplex arm could not implement it). `FlowFacts` has `Copy`, so a slice can change one field with `..facts`.

**As built, from the validator's second pass:**
- D5: `VerdictCache::put` refuses an `Eligible` over a revocation in date, for any leaf, since only a flow already asking can bring one. A closed flow's `Eligible` is not stored at all.
- D15: on h2 what the origin did not process (connection gone before sending, a stream above its GOAWAY, its own REFUSED_STREAM) reaches the client as RST_STREAM REFUSED_STREAM, not a 502. hyper hides a graceful GOAWAY until a request wakes its task, so that request is how the client first hears of it, and the GOAWAY to the client follows. Streams the origin accepted run until the upstream ends them; `CLOSE_GRACE` starts only when none is left. A request that fails on h1 stays a 502.
- D13: a WebSocket's URL is `wss://`, for rules and the log; the upstream's request line is unchanged.
- `ClientWatch::closed_without_request` fires only when `Ended.client_ended`: not on a close by the engine, an upstream's end, hyper's header timeout, or a plain no-ALPN copy, which cannot say who ended it.

A `HookError` resets: RST_STREAM on h2, close on h1 (the contract in `inject/mod.rs`). `body_start` is the first data frame, which is held until `begin` answers. `RequestFacts` carries `url`, `method`, `is_document`, so `PageRequest` is one field copy. Trailers pass through unchanged.

**Cross-stream note:** the DNS stream owns ECH stripping (F9), which needs "would Sieve intercept this name". No app is known at DNS time, so it should strip unless `restricted_suffix(host)` or a host-wide store entry says never, using `ExclusionSlot::get()`. The orchestrator should confirm the stream exists.

## Open questions for the user

**Q1. Which never-decrypt lists?** The decision table says write our own and do not use HttpsExclusions; plan 4.2 and slice 6 still fetch it at runtime, and section 10 Q2 is still open. Default: follow the table. Sieve's own `sensitive` list decides, seeded from a list this stream writes and replaced by signed updates. The HttpsExclusions fetch is built and tested, with `enabled: false`. Cost of the default: a list far smaller than AdGuard's 4,289 entries until it matures, so more sites depend on the floor and on slice 7. Changing it is one word in `SOURCES`. The seed's contents deserve your review before the live check.

**Q2. Browsers with their own DoH.** Under D9 they pass through, since a real ECH cannot be ruled out, so a user with Secure DNS on an explicit provider gets host-level filtering only. Default: accept, and let the log show how often. The alternative is treating every ECH extension as GREASE, as RFC 9849 lets a terminating proxy do, which decrypts those flows too, but it goes against plan 2.9's "passes through".

**Q3. Revocation fetches and the loop guard (F4).** If U5 shows the engine's OCSP and CRL fetches are refused as its own flows, revocation is staple-only until slice 11's CRLite, and 7.2's revoked item fails. Default: leave the guard unchanged in this stream and let U5 decide. The likely fix is relaying the engine's own port 80 flows through `Egress`, which pins outside Sieve's routes and so cannot loop, but changing a safety guard without a live run is not something to do blind.
