# Sieve conventions

How this repo does things, as built by the foundation (2026-10-17). The plan (`docs/plans/2026-10-17-parity.md`) says what to build; this file says how. The look comes from `docs/research/2026-10-17-parity/design-language.md`. If code and this file disagree, fix one of them in the same commit.

## 1. Stack (fixed by the user, versions as installed)

| Layer | What | Version |
|---|---|---|
| Shell | Tauri v2 (Rust 2024 edition, feature `tray-icon`), plugins `store`, `dialog`, `autostart`; `rusqlite` (bundled) for history | tauri 2.12, cli 2.12, rusqlite 0.40 |
| UI | Next.js App Router, `output: "export"` to `out/`, `trailingSlash: true` | next 16.4.2, react 19.3 |
| Styling | Tailwind CSS v4 (CSS-first config, Turbopack loader), shadcn/ui style `radix-nova` | tailwindcss 4.3, shadcn 4.21 (dev dep) |
| Icons, charts | lucide-react; Recharts 3 through `src/components/ui/chart.tsx` | |
| Fonts | bundled, never fetched: `@fontsource-variable/inter`, `@fontsource/jetbrains-mono` (400, 500), `@fontsource/instrument-serif` (400 italic) | |
| Tests | Vitest 5 + jsdom + Testing Library; Playwright 1.61.0 (pinned: it uses the Chromium build already cached on this machine, `chromium-1228`) | |
| Package manager | pnpm 11 only | |

Next 16 differs from older Next. Before touching Next APIs read the guide in `node_modules/next/dist/docs/` (see `AGENTS.md`). Static export rules that bite: no server actions, no route handlers that read the request, no dynamic `[param]` routes without `generateStaticParams`. Deep links use the query string instead (`/apps/?app=<key>`). `useSearchParams` in a page needs a `<Suspense>` boundary or the build fails; the runtime reads `window.location.search` itself, so prefer that.

## 2. Layout

```
src/app/                    routes. page.tsx files are thin: compose components, no logic
  layout.tsx                mounts <AppShell> once (runtime, theme, top bar, toasts)
  globals.css               Tailwind entry: imports, @theme mapping, state layer CSS
src/styles/tokens.css       every design value (the only file allowed colour literals)
src/components/ui/          shadcn primitives, owned by us, already restyled to tokens
src/components/sieve/
  primitives/               state-layer, icon-button, section-icon, segmented
  shell/                    app-shell, top-bar, page, layout-grid, card, empty-state,
                            master-switch, theme-menu, window-controls, wordmark, notice-toaster
  <area>/                   one folder per screen area: home/ (S2), apps/ (S3), ...
src/core/                   pure TS: store, policy, apps, routes, notices, settings/
src/data/                   the data seam: protocol, source, mock-source, tauri-source, poller,
                            settings-store, prng, fixtures/
src/hooks/                  React bindings: runtime, sieve-provider, use-sieve, use-theme, use-hydrated
src-tauri/src/              lib.rs (builder), commands.rs, protocol.rs, netstat/ (S1), history/, tray.rs,
                            dns/ (the DNS filter engine), sysdns/ (Windows DNS: read, point, restore)
tests/laws/                 repo-wide law tests (run by `pnpm test`)
tests/e2e/                  Playwright specs (run by `pnpm e2e`)
scripts/serve-out.mjs       static server for out/ (port 3417, 127.0.0.1 only)
scripts/make-icon.mjs       the Sieve mark (shell/sieve-mark.json) as src-tauri/icons/*, src/app/icon.svg and previews
```

Import direction: `app -> components -> hooks -> data -> core`.
- `src/core` imports only from `src/core`, plus `import type` from `@/data/protocol`. No React, Next, Tauri, DOM, `Date.now`, `new Date()`, `Math.random` (law 5). Time inside a derivation is the newest snapshot's `t`.
- `src/data` may import `src/core` (for example `isActiveFlow`).
- Components read data only through hooks (`useSieve`, `useSetting`, ...), never by importing a source or the store directly.

## 4. Tokens and styling

- All values live in `src/styles/tokens.css` as role variables, dark under `:root, :root[data-theme="dark"]`, light under `:root[data-theme="light"]`, both with the same names (law checks). `<html data-theme>` is set by `useThemeSync` from the setting `appearance.theme` (system, light, dark; default dark).
- Tailwind's default colour palette is removed, so only role utilities exist:
  - surfaces `bg-bg bg-surface-1 bg-surface-2 bg-surface-3 bg-inset bg-scrim`, lines `border-outline border-outline-strong`
  - text `text-on-surface text-on-surface-muted text-on-surface-faint`
  - accents `primary on-primary blocked on-blocked warning info` (as `bg-*`, `text-*`), containers `bg-mint-container text-on-mint-container` (also peach, lilac)
  - chart `series-1` to `series-6`, `series-other`; heatmap steps as variables `bg-(--heat-mint-0)` to `-3` (also lilac, peach); `bg-track`, `bg-selected` (accent at 16%)
  - shadcn names (`bg-card`, `bg-popover`, `text-muted-foreground`, `ring`, `destructive`, ...) are aliases of the roles, never separate values.
- Type: `text-display text-title-lg text-title text-kpi text-body text-body-strong text-label text-caption text-mono` (size, line height and weight together). Numbers get `tabular` (class) or `data-numeric`. Hosts and paths: `font-mono text-mono`. The serif (`font-serif italic`) appears at most once per screen, only through `EmptyState` or an onboarding hero.
- No containers (the user, 2026-10-17: "lose all containers and cards"): content sits flat on the page background. No surface fill, border box, elevation, radius or inner padding around a block of content, a KPI or a section icon; blocks are separated by space (the grid gutter, the settings column gap) and type. Surfaces, radii and elevation remain for things that float or are pressed: menus, tooltips, dialogs, sheets, toasts, buttons, switches, segmented controls, inputs and search.
- No dividers (the user: "hr's are ugly, margins and padding are always better"): no line between things anywhere in `src/components`: no `border-t`/`border-b`/`border-y` as a separator, no `divide-*`, no `<hr>`, no Separator part (the unused shadcn table, scroll area, toggle group and the menu and select separators were removed). Rows, list items, sections and dialog footers are set apart by space from the ladder, with more space between groups than inside them (app rows `gap-1`, app groups `gap-6`; setting rows `gap-4`, sections `gap-8`; DNS card parts `gap-6`, adapters `gap-3`). Pressed rows keep a 44 px height. Focus rings and a form control's all-round border are not separators. Laws: `tests/laws/no-dividers.test.ts` (law 7, static) and the row check in `tests/e2e/alignment.spec.ts`. Chart grid and zero lines are drawn as 1 px fills, part of the chart.
- Radii: `rounded-xs` 4 (cells, bar ends), `rounded-sm` 8 (inputs, monograms), `rounded-md` 12 (menus, tooltips), `rounded-xl` 24 (dialogs), `rounded-full` (buttons, chips, switches, segmented, search).
- Elevation: `shadow-l2` thumbs, `shadow-l3` menus and tooltips, `shadow-l4` dialogs, sheets and toasts, `shadow-inset` search and inputs. Never on a content block. The only glow is the master switch (`animate-breathe`).
- Spacing: only the ladder 4/8/12/16/20/24/32/40, that is Tailwind steps `0 1 2 3 4 5 6 8 10` for padding, margin and gap in `src/components/sieve` and `src/app` (law). Sizes (`h-14`, `size-9`) are free.
- Motion: `duration-(--motion-fast|base|emph-in|emph-out|chart)` with `ease-standard`, `ease-emph-in`, `ease-emph-out`. Under `prefers-reduced-motion` `--motion-chart` and `--motion-ripple` become 0, ripples are not spawned and pulse and shimmer stop. Live chart updates never re-animate from zero.
- Breakpoints: `two:` at 960 px and `three:` at 1280 px (plus `max-[640px]:` for the narrow browser mock). Do not use `md:`/`lg:` for page layout.
- Banned (law 1): colour literals outside tokens.css (hex, rgb, hsl, oklch, ...), `dark:` classes anywhere in `src`, `var(--x)` of a variable nobody defines.
- Class merging: always `cn` from `@/lib/utils` (ui primitives too, never `from "cn"` directly). It is `createCn` with the type roles registered as font sizes; without that, `text-label text-on-surface-muted` lost the size and filled buttons lost `text-on-primary` (`src/lib/utils.test.ts` keeps the list equal to the `--text-*` roles in globals.css).
- Series colours by slot: `seriesTone(slot)` in `home/series-tone.ts` spells out `fill-series-N`, `bg-series-N/20`, ... (never build `var(--series-${n})`, the variable law cannot see it).

## 5. UI placement and components

- A screen is `src/app/<route>/page.tsx` that renders `<Page title meta? action? notice? fill?>` with its regions on a `<LayoutGrid>` of `<GridRegion span={3|4|6|8|9|12}>`.
- **Layout grid (one for every page, defined once).** Tokens in `src/styles/tokens.css`: `--page-max` 1920, `--page-pad` 24, `--gutter` 24, both 16 under 640 px (`@media (width < 640px)` in tokens.css, the same breakpoint as `max-[640px]:`), `--page-header-h` 64. Utilities in `globals.css`: `page-container` (width 100%, at most `--page-max`, centred, `--page-pad` each side) and `layout-grid` (12 equal columns, `--gutter` between columns and rows). Primitives in `shell/layout-grid.tsx`: `LayoutGrid`, `GridRegion` (span from 960 up, 12 below). The top bar's inner row and `<Page>` (header row and content) are both a `page-container`, so:
  - the top bar's logo, the page title and every region's left edge sit on one line; the top bar's right controls, the header actions and every region's right edge sit on another;
  - regions start on a column start and end on a column end, spans side by side add up to 12, so a row ends on the container's right line;
  - a max width only ever applies to the whole container, never to one list or column.
  Never set side padding, a max width or a gutter on a screen; never nest a second 12 column grid. Law: `tests/e2e/alignment.spec.ts` (edges within 1 px of the grid lines, no overlap, at least the gutter between siblings, no sideways overflow in a region, the legend or the range control, headers in a row share a top), at 1280x800, 960x800 and 375x812.
- A titled block of content is a `<Card title icon? tone? action? state?>`, flat (see section 4). `state` is `{kind:"ready"}` (default), `{kind:"loading"}` (skeleton), `{kind:"empty", line, body?, action?}`, or `{kind:"error", message}`. Each has its own error boundary (`CardBoundary` and `CardBody` are exported for blocks that are not one Card, such as the Home KPI tiles and the Apps list). A Card is as tall as its content; Home passes `className="h-full"` to fill a bento cell (a built-in `h-full` stretched the Settings Filtering card to the height of the wrapper it shares with the DNS filter card). When title and action do not fit on one line, the action wraps under the title.
- No status chip (the user: the Live chip was redundant beside the Sieving switch). The master switch carries `data-phase` and a screen-reader-only live region that speaks the phase; a timed pause is shown once, on Home, as the paused banner (until when) with the Resume pill as its one control.
- `<Page fill>` makes the page exactly as tall as the content area at 1280+, so a `three:flex-1` grid takes the height left under the header. Do not subtract sibling heights in a calc.
- Scrolling (the user: "only vertical styled scroll"): the window never scrolls. `AppShell` is a window-tall column (`overflow-hidden`, positioned) with the top bar and one content area, `[data-scroll-root]` (positioned, `overflow-y-auto`, `overflow-x-hidden`), the only thing that scrolls, vertically only, under a top bar that stays put. Its scrollbar is the thin token one (`--scrollbar-w` 8, thumb `--outline-strong`, `::-webkit-scrollbar` rules in globals.css, which WebView2 honours; `scrollbar-width`/`scrollbar-color` only where those rules are not supported, because Chromium drops the webkit rules for an element that sets them). The gutter is always reserved (`scrollbar-gutter: stable`) and the top bar keeps `--scrollbar-w` free on its right, so both containers end on one line. Sticky elements stick inside the content area (`top-4`). Home fits without scrolling from 1280x800 up. Law: `tests/e2e/scroll.spec.ts` (every page at 960x640, 1280x800 and 1600x1000).
- Tooltips: every custom tooltip is `FloatingTooltip` (`primitives/floating-tooltip.tsx`): a portal to `document.body`, fixed, beside the pointer, flipped and clamped inside the window by `tooltipPosition` (the chart moves its own on pointer move with `placeTooltip`). A tooltip inside the page once widened the window. An element with a custom tooltip has no native `title` too (the scroll law hovers the last heatmap cell and the chart's right edge and checks both).
- Live charts: the Home chart (`home/activity-chart.tsx`) is hand-drawn SVG, not Recharts, because Recharts remounts its area paths on every data change. x is absolute time from an origin fixed for the mount, in a fixed unit (one hour spans the plot's 1000 units); the window (`model.windowMs` ending at `model.end`) lives only in the plot group's transform (`translateX` slides a bucket per tick, `scaleX` rescales on a window switch), so path nodes and existing vertices survive both. Never key or remount the chart: switching 5 min, 1 h, Session, 24 h, 7 d, 14 d changes only the time range (the plot keeps its box; law in `alignment.spec.ts` and `home.test.tsx`). The window is always the full choice: where the data starts inside it, a faint boundary says "Sieve started HH:MM" (live) or "Saved from ..." (history). While a period is read the chart keeps its series with no points, never a loading card. `d` morphs only when the bucket times did not change (legend toggle). Use Recharts through `ui/chart.tsx` for static charts.
- Pressables: shadcn `<Button>` (pill; variants `default` filled mint, `secondary` tonal, `outline`, `ghost` text, `destructive` tonal pink, `link`), `<IconButton label>` (round 36, `label` is required and becomes `aria-label`, optional `badge`, `toggled`), `<Segmented items value onChange label>` for in-page choices (Day/Month/Year, chart windows), `<SegmentedNav>` only in the top bar. Anything custom and pressable is `relative overflow-hidden` with `<StateLayer />` as its last child.
- The Sieve mark (logo, app icon, tray, favicon): a ring with three parallel diagonal lines clipped inside it, mint on transparent. One geometry, `src/components/sieve/shell/sieve-mark.json`: `SieveMark` draws it in `currentColor` (`text-primary`) in the top bar; `node scripts/make-icon.mjs` writes `src-tauri/icons/source.svg` (colour: the dark `--primary` read from tokens.css), `src/app/icon.svg` (the favicon), a 1024 px PNG (@resvg/resvg-js) and runs `pnpm tauri icon` on it; previews at 16, 32 and 256 px go to `test-results/screens/icon-*.png`. The tray uses the default window icon, dimmed while not live. Law: `tests/laws/icon.test.ts`.
- Icons: lucide-react, `strokeWidth={1.75}`, sizes 16/20/24; beside a title or a KPI label as a plain `<SectionIcon size={16|20} tone>` (no tile; `mint` tints it when something is on). An app is shown by its own icon through `<AppIcon exe>` (see App icons above), with its monogram as the fallback.
- Copy: sentence case, plain words, no em dashes. Never claim filtering that is not happening. Home law (`home.test.tsx`, `dns.spec.ts`): while the DNS filter is not running, Home never says ads, trackers or blocked; while it runs, "blocked" appears only inside `[data-dns-derived]` tiles and ads or trackers never. DNS filtering is system wide: no copy says an app is filtered or blocked. One warm serif line per screen at most.
- Accessibility: every icon-only control has an accessible name (shell test checks the shell); dialog titles may be `sr-only`; status text never relies on colour alone (the master switch speaks the phase in words).

## 6. Settings and data switches

- Add a setting: one entry in `REGISTRY` with `kind` (`enum`, `boolean`, `number`, `map`, `list`, `dataSwitch`), `section` equal to the key prefix (`appearance.theme` is in `appearance`), `label`, `help`, `default`, optional `requires`. Adding a key with a default does not bump `SETTINGS_SCHEMA`; renaming or retyping one does, with a step in `migrate.ts`.
- Anything that changes traffic or the system is a `dataSwitch`: default `false`, `liveCheck: "live_<what_it_proves>"` naming an `#[ignore]`d Rust test of the same name (registry law). Today:
  - `filtering.dns` -> `live_dns_filter_resolves_blocked_domain` (`dns::engine::tests`, run with `cargo test --manifest-path src-tauri/Cargo.toml --lib -- --ignored live_dns`); in the app the same proof is `dns_self_check` against the running proxy, recorded in `passedChecks`.
  - `filtering.systemDns` (requires `filtering.dns` and its passed check) -> `live_system_dns_points_at_sieve` (`sysdns::commands::tests`, READ ONLY: passes only after the user pointed Windows at a running Sieve). The switch mirrors Windows: on load it is set from what Windows does, never the other way; only a flip by the user points or restores; when Windows changes by itself (restore-dns.ps1 run by hand) the switch follows.
  - Per-app DNS exemption is not a setting: Windows sends every lookup through one service, so exempting one app needs a network driver, which Sieve does not have.
  - Not a switch: `filtering.upstreams` (list of upstream addresses, element shape `upstream`, default 1.1.1.1 and 9.9.9.9), handed to `dns_start`.
- A feature that needs a switch reads `requires` or the key constants in `src/core/dns.ts`; UI never spells a data switch key (registry law). An import never turns a data switch on.
- What needs a switch: DNS proxying, pointing Windows DNS, a system or local HTTP proxy, WFP or firewall rules, certificate installs, anything writing outside the app's own data dir. What does not: reading the TCP/UDP owner-pid tables, process image names and version info, the running services list (EnumServicesStatusExW, enumerate access only), adapter DNS servers, the Tcpip registry values, the process list (read only, no admin), the settings file, the file dialog.
- Safety rules for the system write (sysdns): backup and `restore-dns.ps1` are written before anything changes and never overwritten; pointing needs the filter on both loopback addresses with a passed self check; on load, Windows pointed at loopback with Sieve's backup starts the filter whatever its switch says, and a filter that cannot start puts a banner with "Restore my DNS" on Home; turning DNS filtering off while pointed restores first; tray Quit and closing the window while pointed ask first. Agents and tests never run point, restore, netsh, Set-DnsClientServerAddress or any elevation; only the user does, in the app.
- Never needed: drivers, system proxy, firewall changes. Admin rights only for the one elevated DNS script, through the Windows prompt.
- A setting only the desktop app can apply (today `startup.launchAtLogin`, the current user's Run entry through the autostart plugin, written only when the user turns it on) is `desktopOnly: true`; the browser shows it locked with the reason.
- Map and list settings declare their element shape (`of`), so a corrupt stored `apps.levels` or `apps.pinned` reads as the default. UI code never names a data switch key: it reads `requires` (registry law).

## 8. Rust side

- `lib.rs` registers plugins and `generate_handler![...]`; each command lives in `commands.rs` and is `async`, running blocking work in `tauri::async_runtime::spawn_blocking`; it returns `Result<T, String>`.
- Module errors are `thiserror` enums (`NetstatError`), turned into strings only at the command boundary. No `unwrap`/`expect` outside tests; clippy runs with `-D warnings`.
- Read calls to Windows only, with one declared exception: `sysdns::win::run_elevated` (one PowerShell script, verb "runas", UAC). The `windows` crate features each module needs are listed with a comment in `Cargo.toml`. No drivers.
- Tests never bind port 53 (use `127.0.0.1:0` / `[::1]:0`). For port 0, `bind_pair` tries random ports of the dynamic range for UDP and TCP together: Windows reserves separate, moving TCP and UDP port ranges, and a port the OS picked for one protocol kept landing in the other's exclusion (WSAEACCES, 10013).
- Capabilities (`src-tauri/capabilities/default.json`) grant window controls, `store:default` and `dialog:default`. Add a permission only with the command or plugin that needs it.
- Each worktree keeps its own `src-tauri/target` (the default). First build is about 2 minutes.

## 10. Known gaps (foundation)

- `pnpm tauri dev` was not run (tests only); window controls, drag region, plugin-store and dialog are compiled and permissioned but not looked at. CSP is `null` until someone checks Next's inline scripts under a strict policy.
- The light theme chart series (`--series-1` to `-6` in light) and light `--blocked` are proposals, not measured; dark `--on-surface-faint` contrast is unverified. All motion values are proposals.
- No inline theme script: a user who picked light sees the dark default for one frame on load.
- Process names (feedback round 1): a process whose exe Windows hides is named by the display names of the services it hosts (`netstat::process::service_label`: one name, or the first by name and "and N more"), else `pid <n>`. Pid 0 (System Idle) rows are TIME_WAIT leftovers and are dropped in `netstat::assemble`, so they are no app, no series and no count. History saved before this change can still hold a "System idle" app until its buckets age out (2 d minute, 35 d hour, 400 d day grain). Live read: `live_service_names_name_running_service_hosts`.
- `groupApps` follows the plan's identity rule (ProductName first). Windows' own exes share one ProductName, so explorer, svchost and SearchHost group as one app, "Microsoft Windows Operating System" (visible in the mock). S2/S3 should decide whether system apps group by exe stem instead.
- `useSieve` rerenders every consumer on every store change (1 Hz by default). Home selects `s.snapshots` (same array until a new sample) and caches per-snapshot counts in a WeakMap, so a status change does not recompute the chart.
- S2 kept the ProductName identity: the Windows exes show as one Home series, "Microsoft Windows Operating System". The exe-stem decision for system apps is left to S3 (Apps).
- Home's Session window keeps at most 2 h (`SESSION_MAX_MS`). Home declares the Session window for as long as it is shown (the series set comes from the whole session), so the ring holds every snapshot of the last 2 h whatever window is picked (about 7200 full snapshots at 1 s). Memory at those sizes is not measured; a compact per-tick count history would be the fix if it is too much.
- Wave 2: the tray, its dimmed icon, launch at startup and the SQLite file were not looked at in a live window (no `pnpm tauri dev` in a slice run); they are covered by Rust unit tests and by TS tests against a fake `Desktop`. The paused banner derives from `status.pausedUntil`, so it is right after navigating and when the tray pauses.
- DNS phase B (2026-10-17): nothing was looked at in a live window. Not verified on the machine: the UAC prompt and the elevated point and restore scripts (only their text is unit tested), `Set-DnsClientServerAddress` with addresses of one family leaving the other family alone (the restore resets first, so either behaviour ends right), Windows actually sending IPv6 lookups to [::1]:53, binding the real port 53, the tray Quit and close-button question, `onCloseRequested` with the `core:window:allow-destroy` permission, AdGuard detection against the real process (the read itself is tested). AdGuard for Windows intercepts DNS with its driver, so with AdGuard's DNS protection on, Sieve's filter sees nothing.
