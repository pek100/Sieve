# Sieve: parity plan against AdGuard for Windows

Date: 2026-10-17. Inputs: the capability table (`docs/research/2026-10-17-parity/table.md`, 79 rows), the two survey reports beside it, and the design language (`design-language.md`). Conventions every slice follows live in `docs/conventions.md`.

The user's criteria, verbatim: "should be a clean minimalistic interface, that show a chart of what apps are currently being sieved, the app's name is Sieve, and i think let's build it in tauri + nextjs + tailwind + shadcn. color pallete should be pastel dark + vibrant retro in my opinion, if it makes sense(both images), and material ui like." and "check carefully" (the survey).

## 1. Stack

Fixed by the user: Tauri v2 + Next.js (App Router, static export) + Tailwind v4 + shadcn/ui, pnpm. From Michael's defaults where the user said nothing: React 19, TypeScript strict, lucide-react, Recharts via the shadcn chart component, Vitest + Testing Library, Playwright, bundled Fontsource fonts. Rust side: `windows` crate (IP Helper and process APIs, read-only), `serde`, `thiserror`, `tauri-plugin-store`, `tauri-plugin-dialog`. No Convex and no network backend: Sieve is a local app and the data never leaves the machine.

## 2. Native model (the minimal basis)

Before any screen, every AdGuard capability was mapped onto these primitives. A new primitive is admitted only when a row cannot be expressed in them.

| # | Primitive | Owner | What it is |
|---|---|---|---|
| B1 | `Snapshot` | `src/data/protocol.ts` + `src-tauri/src/protocol.rs` (v1) | One sample of the machine: `t`, `processes[]` (pid, exe, name, product), `flows[]` (pid, proto, family, local, remote or null, state). Raw facts only, no judgement (S16). |
| B2 | `SieveSource` | `src/data/source.ts` | `sample(): Promise<Snapshot>` plus `kind` and `history(range)`. Two implementations: `tauri` (Rust reads `GetExtendedTcpTable`/`GetExtendedUdpTable` with `TCP_TABLE_OWNER_PID_ALL` and `UDP_TABLE_OWNER_PID`, resolves exe with `QueryFullProcessImageNameW` and product name from version info) and `mock` (seeded). Cadence owned by one poller in `src/data/poller.ts`. |
| B3 | Derivations | `src/core/` | Pure functions over snapshots: `groupApps` (app identity = product name, else exe stem; executables are children), `category` (derived from the exe path: Windows dir -> system, user-pinned -> mine, else apps), `isSieved`, `series` (per-app activity over a sliding window), `kpis`, `heat` (hour x weekday buckets). Nothing derived is stored (S23). |
| B4 | `level` (per app) | `src/core/policy.ts` | One ordered quantity `off < watch < sieve` replacing AdGuard's three dependent switches (route, filter, HTTPS). Effective level = `min(requested, ceiling)`; the ceiling is derived from data switches (watch always; sieve only when `filtering.perApp` is on and its live check passed). The muted lower switches of AdGuard fall out of the ordering for free. Update 2026-10-17 (DNS phase B): sieve used to need `filtering.dns`; a DNS proxy cannot attribute lookups to apps (they all come through the DNS Client service), so DNS filtering is system wide and `sieve` now needs `filtering.perApp`, declared unavailable (it needs a network driver). |
| B5 | Settings registry | `src/core/settings/registry.ts` | Every setting as data. The settings screens, the searchable advanced list, export, import, reset to defaults and the data-switch gating are all derived from it. |
| B6 | Domain list | backlog | One list primitive `{kind: allow or block, scope, entries[], enabled}` with add, edit, remove, import, export, search, undo. Covers rows 13 (DNS rules), 22, 23, 36. |
| B7 | Notice bus | `src/core/notices.ts` + toaster | One queue for in-app toasts (with undo), banners and later desktop notifications (rows 4, 75, 76). |

What becomes redundant against AdGuard (named so it is never rebuilt):
- The route / filter / HTTPS triple and its "muted when parent is off" rules: one ordinal (B4).
- General settings, Advanced settings, per-module option lists and their reset/search menus: one registry (B5) rendered by one settings view.
- Five allowlist/blocklist screens (ad allowlist, DNS allow/block, parental allow/block): one domain list (B6).
- The five statistics drill-down screens (app, executable, company, domain, subdomain): one entity view keyed by a group-by axis over B1 and B3 (backlog).
- AdGuard's tile row "chart" and the dead home stats card: replaced by the live series chart (B3 `series`).
- A separate "Statistics paused" mode: pausing is the poller stopped; the paused banner derives from poller state.

Honest measurement: the read-only tables give connections, remote hosts, states and listening ports per process. They do not give bytes (per-connection byte counters need `SetPerTcpConnectionEStats`, which needs admin), ads or trackers. So every counter in Sieve names connections or hosts until a filtering data switch is on. "Being sieved" = an app whose effective level is at least `watch` and that has at least one non-listening flow in the newest snapshot.

## 5. Ordered plan

2. Three slices in parallel worktrees (section 6): S1 live connection source, S2 Home with the live per-app chart, S3 Apps screen with per-app level. Backlog, in order of value for the goal: persisted history (row 77) which unlocks periods (51) and the real heatmap; connections log (56 to 58); settings view over the registry (68 to 70, 6); tray (74); B6 domain lists (13, 22, 23, 36); first-run (47, 48); entity drill-down by host (54); the first real filter `filtering.dns` (38 to 42) behind its data switch; everything else G3.

## 6. Slices

### S1: Live connection source (Rust, read-only)

Spec. Implement `src-tauri/src/netstat/` behind the existing `netstat::snapshot() -> Result<Snapshot, NetstatError>`:
- `tables.rs`: `GetExtendedTcpTable` (AF_INET and AF_INET6, `TCP_TABLE_OWNER_PID_ALL`) and `GetExtendedUdpTable` (`UDP_TABLE_OWNER_PID`) with the size-probe then fill pattern (retry on `ERROR_INSUFFICIENT_BUFFER`).
- `decode.rs` (pure, unit tested with byte fixtures): ports from network byte order, IPv4 and IPv6 addresses, scope ids, TCP state codes 1 to 12 to the protocol's state names, listening rows have `remote: null`, UDP rows have state `none`.
- `process.rs`: pid to exe via `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` + `QueryFullProcessImageNameW`; product name via `GetFileVersionInfoW`/`VerQueryValueW` (`\StringFileInfo\...\ProductName`), cached per exe path. Access denied (system processes, pid 0 and 4) gives `exe: null`, `name` from a pid label ("System", "System idle") only for pids 0 and 4, otherwise `name: "pid <n>"`; never a guessed name.
- Snapshot `t` from the Rust clock (glue, declared), not from the TS side.
- `src/data/tauri-source.ts`: `invoke<Snapshot>("net_snapshot")`, validates `v === PROTOCOL_VERSION` and throws on mismatch.
- Add the `windows` crate features needed (`Win32_NetworkManagement_IpHelper`, `Win32_Networking_WinSock`, `Win32_System_Threading`, `Win32_Storage_FileSystem`, `Win32_Foundation`).

Acceptance.
- `cargo test --manifest-path src-tauri/Cargo.toml` passes, including decode tests for: a port in network byte order (bytes `0x01 0xBB` read as 443), an IPv4 and an IPv6 address, every TCP state code, a listening row with no remote, a UDP row.
- The Rust protocol test deserialises `src/data/fixtures/snapshot-v1.json` and re-serialises an equal value.
- `cargo clippy ... -- -D warnings` passes; no `unwrap` outside tests.
- `live_snapshot_reads_own_process` (`#[ignore]`) opens a TCP listener on 127.0.0.1:0 in the test, takes a snapshot and finds a flow with the test's own pid, that port and state `listen`, and the test's exe path. It runs without admin.
- No call writes system state: the only Win32 calls are the read functions named above (reviewer greps the diff).
- `pnpm check` still passes; the browser mock path is unchanged.

Touches: `src-tauri/src/netstat/**`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`, `src/data/tauri-source.ts`, `src/data/tauri-source.test.ts`. Versioned seams: none (implements protocol v1). Live check: yes, `cargo test -- --ignored live_snapshot_reads_own_process`, then `pnpm tauri dev` showing real apps.

### S2: Home: live per-app chart, KPIs, top apps, heatmap

Spec. Data first:
- `src/core/series.ts`: from the store's snapshot ring buffer, build per-app points (active non-listening flows per app per tick) over the chosen window. Series count = number of `--series-*` tokens (6, read from one exported constant `SERIES_COUNT`), ranked by window total; the rest folds into "Other". Ranking is sticky: an app keeps its colour while it stays in the top set so colours do not jump between ticks.
- `src/core/kpis.ts`: apps sieved now, active connections, distinct remote hosts, listening ports; each with a delta against the start of the window (up, down, flat).
- `src/core/heat.ts`: hour x weekday counts from `source.history()` (mock: 4 weeks; Tauri: session-only until row 77, caption says "Since Sieve started").
UI (`src/components/sieve/home/`), on the foundation `BentoGrid`:
- Row 1: hero chart card (8 columns at >= 1280): stacked area per app, crosshair tooltip listing the hovered tick's apps with values, legend chips that toggle a series (on, off with hollow swatch), window control (segmented: 5 min, 1 h, session). Live updates append and slide; they never re-animate from zero; chart morph 400 ms, off under reduced motion.
- KPI block (4 columns): 2x2 KPI tiles with icon tile, delta chip, label, tabular number with ticker; at most one accent container tile.
- Row 2: top apps ranked list (icon or monogram tile tinted with the app's series colour, name, thin progress bar, count), heatmap card (hour x weekday, 4 steps, legend, cell tooltip).
- Header row: page title "Sieving now" as plain text, pause pill (5, 15, 60 minutes, resume), status chip derived from poller.
- States: skeleton on first load, empty (scenario `empty`: one serif line plus one action to resume or open Apps), error card naming the source error (scenario `error`), paused banner via B7.
